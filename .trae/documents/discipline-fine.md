# 风纪罚款功能方案（已定稿，待开工命令）

## 背景与目标

给风纪监察部实际权力：对违规员工处以摸鱼币罚款。设计原则：罚款即销毁、无资金转移收益、全程留痕可撤销、公开透明。

## 已锁定的决策（用户确认）

1. **资金流向**：罚款即销毁；执法者获得 20% 抽成（唯一回流，计入每人每日 5 币津贴封顶）
2. **执法权限**：后台可指派执法部门（默认风纪监察部）；**每日可罚次数按执法者职级区分**（可配置映射）
3. **金额**：单次固定 5 摸鱼币（可配置）；执法者抽成 20%（可配置）；抽成与每日 5 币津贴封顶共享额度
4. **余额不足**：照罚，扣到 0 为止（实扣 = min(余额, 罚款额)）；抽成按**实扣金额**的 20% 向下取整
5. **申诉**：V1 不做；罚款成功文案附"如对本次罚款有异议，请保存截图并向经理或总监职级以上的员工反馈"
6. **冷却**：同一执法者 10 分钟（可配置）
7. **附带指令**：`/我的罚款` 查自己被罚记录（私聊）
8. **参数**：全部后台可设置

## 指令设计

| 指令 | 场景 | 说明 |
|---|---|---|
| `/罚款 [理由]` 或 `/罚 [理由]` | 仅群聊，**引用回复**被罚人消息 | 按引用锁定目标（直接用 uid，无重名问题）；理由可选 |
| `/罚款 名字 [理由]` 或 `/罚 名字 [理由]` | 仅群聊 | 按注册名定位；理由可选；重名报错并列出工号候选 |
| `/罚款 #0001 [理由]` | 仅群聊 | 按工号定位（备用） |
| `/我的罚款` | 仅私聊 | 本人被罚记录（近 10 条 + 累计被罚总额/次数） |

- 两种形态自动区分：有消息引用 → 引用形态（引用优先于名字参数）；无引用 → 名字形态
- 理由可选：为空时记录与公告注明"未填写理由"
- `/罚` 归一化为 `/罚款`（前缀剥离顺序注意 `/罚款` 先于 `/罚`）
- 加入 `_COMMAND_DEFINITIONS` 种子（`/罚款`、`/我的罚款`）；`/我的罚款` 进 `_DIRECT_COMMANDS` 白名单

## 规则

| 项 | 默认 | 可配置 |
|---|---|---|
| 单次罚款额 | 5 币 | ✓ |
| 执法者抽成 | 20%（按实扣取整，入账走津贴封顶） | ✓ 百分比 |
| 每日抽成封顶 | 与部门津贴共享 5 币/日 | 沿用现有封顶 |
| 执法者每日次数 | 按职级映射（见下） | ✓ 逐职级 |
| 冷却 | 同一执法者 10 分钟 | ✓ 分钟数 |
| 被罚人每日上限 | 无限制 | ✓ 次数（0=不限） |
| 执法部门 | 风纪监察部 | ✓ 下拉指派 |

默认职级配额（执法者）：

| 职级 | 次数/日 |
|---|---|
| 实习生 | 0 |
| 正式员工 | 1 |
| 小组长 | 2 |
| 副主管 / 主管 | 3 |
| 部门副经理 / 部门经理 | 5 |
| 部门副总监 / 部门总监 | 8 |
| 公司负责人 | 10 |
| 核心董事会 | 20 |

禁止项：不能罚自己、不能罚同部门（执法部门内部）、不能罚未入职玩家。
执法者非指派部门成员 → 拒绝；职级配额为 0 → 拒绝并提示。

## 资金与记账

- 被罚人：`_apply_balance_change(-实扣, source="discipline_fine")`，余额可扣到 0 不为负
- 执法者抽成：走 DepartmentAllowanceRecord 台账 `kind="fine"`，与 7 种津贴共享每日 5 币封顶；封顶后实发 0 静默
- 津贴通知动作词映射新增：`fine → 风纪执法抽成`
- 撤销：退还被罚人实扣全额（`source="discipline_fine_refund"`）；**不追回**执法者已得抽成
- 抽成为 0（实扣 0 或封顶）时记录留痕

## 文案

- 群公告：`【风纪罚款】稽查人（风纪监察部）对 目标 处以 5 摸鱼币罚款（余额不足，实扣 M），理由：xxx / 未填写理由\n如对本次罚款有异议，请保存截图并向经理或总监职级以上的员工反馈。`
- 被罚人私聊：`【风纪罚款】你被处以 5 摸鱼币罚款（实扣 M），理由：xxx。当前余额：K。如对本次罚款有异议，请保存截图并向经理或总监职级以上的员工反馈。`
- 执法者私聊回执：`已成功扣款 M 摸鱼币（目标：xxx，理由：xxx / 未填写理由），获得 1 摸鱼币津贴（今日津贴 3/5）。`；**封顶后仍可执行罚款**，回执提示改为 `获得 0 摸鱼币津贴（今日津贴已满 5 币）`
- 抽成入账仍走【部门津贴】通知体系（kind=fine，动作词"风纪执法抽成"），实发 0 时不发津贴通知（回执里已有说明）

## 边界情形

- 引用形态：引用目标未入职（含机器人消息）→ 拒绝；引用自己的消息 → 按罚自己拒绝
- 名字形态：名字缺失且无引用 → 用法提示（两种形态示例）
- 执法者职级配额为 0 / 未配置 → 拒绝："你的职级今日无可用的罚款次数"
- 当日次数用尽 → 同上提示
- 冷却中 → 提示剩余等待时间
- 实扣 0（余额本就为 0）→ 照常留痕，公告注明"实扣 0"，抽成 0
- 抽成封顶（今日津贴已满 5）→ 罚款照常执行，回执注明"今日津贴已满 5 币"
- 目标重名 → 报错并列出 `#工号 名字` 候选
- 撤销后重复撤销 → 拒绝
