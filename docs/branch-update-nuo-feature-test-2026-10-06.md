## 3. 生日祝福与入职周年

### 3.1 登记与隐私

- 新增 `/设置生日`、`/我的生日`、`/本月生日`。
- 支持 `5-20`、`5/20`、`05.20`、`5月20日` 等公历写法，也可提供年份；群内不公开年龄。
- 首次登记不消耗修改次数，此后默认每个自然年最多修改一次，次数由后台配置。
- 支持“不公开”设置。当前实现中，不公开生日不进入公开寿星名单，不公告、不发生日礼金，也不享受生日特权。
- 2 月 29 日生日在平年按 2 月 28 日处理，入职周年沿用相同日期处理逻辑。

### 3.2 定时祝福、礼金与随礼

| 配置或行为 | 默认规则 |
| --- | --- |
| 总开关 | 新初始化配置默认关闭 |
| 前一天预告 | 默认 20:00，可配置和关闭 |
| 当天祝福 | 默认 09:00、12:00、17:00，支持配置多个时刻 |
| 多时刻限制 | 最多 10 个有效时刻，去重并排序 |
| 生日礼金 | 默认 20 摸鱼币，可调整或设为 0 |
| 重复发放保护 | 同一员工同一年度礼金仅发一次；多个祝福时段不会重复发钱 |
| 同日多人生日 | 合并展示当天寿星 |
| 随礼 | `/随礼 金额`；多人生日时使用 `/随礼 姓名 金额`，也支持回复目标消息 |
| 随礼时限 | 默认有效至当天 24:00，也可配置更短窗口 |
| 随礼金额 | 默认单次上限 20 币；每人每场只能随一次，不能给自己随礼 |

随礼是员工之间的余额转移，不属于公司新增发币。窗口结束后公布人数与总额。每个祝福时段有独立公告去重记录，礼金和公告重复次数分别控制。

后台可设置当天补发规则；整天离线不自动补发上一天的生日活动。名单中提供“试跑”和“补发”：试跑用于查看文案，补发会执行实际业务，二者效果不同。

### 3.3 生日特权与后台

生日当天默认包括打卡基础奖励两倍、商店八折、购彩前 5 注免单、随机事件奖励增加 50%，均可配置。购彩免单在当天祝福发出后开放，不因多个群或多次公告重复增加额度。

后台提供生日总开关、预告和祝福时刻、礼金、修改次数、随礼、生日特权、入职周年、模板和群开关。生日名单支持查看、试跑及补发。

修复了生日页面对群列表包装格式的处理，以及保存配置时版本号未同步的问题。

## 4. 大话骰子

### 4.1 完整玩法

基本流程：

```text
/大话骰子 → /加入 → /开始 → 私聊收骰 → 群内叫骰 → /开骰 → /继续 或 /结束游戏
```

- 每位参与者每轮 5 个骰子，个人骰子通过私聊发送；私聊 `/看骰` 可复查。
- 开局前检查参与者的私聊通道，缺少可用通道时提示处理；发骰完成后进入叫骰阶段。
- 每轮随机选出万能点；万能点被明确叫过后失效，只作为自身点数计算。
- 叫骰须符合加码规则；`/开骰` 公布并判断胜负。
- 胜者获得向败者发布任务的提示，游戏本身没有新增一套独立输赢扣发币规则。
- `/继续` 开下一轮，调整为从上一轮开骰者的下一席开始。
- 支持报名超时、行动超时、中途退出、人数不足结束和恢复处理。

### 4.2 数据与整局口径

`/大话骰子数据` 展示本局及群内跨局累计数据，包括开牌、败露、拆穿、受罚等统计。

用于“超级游戏王”的参与次数按整局计算：同一游戏 ID 同一员工最多计一次。多次叫骰、多次开骰、多轮继续不会增加整局次数；有有效开牌结算的轮次才构成有效参与依据。

### 4.3 新后台管理

| 参数 | 默认值 | 范围 |
| --- | --- | --- |
| 开启玩法 | 开启 | 开启／关闭 |
| 最少开局人数 | 2 人 | 2–10 人 |
| 回合超时 | 120 秒 | 30–600 秒 |

当前配置作为全局规则应用于各群；创建报名局还受该群游戏总开关和大话骰子群开关控制。关闭玩法后，已有报名局和进行中的对局仍可操作。

状态页展示开启状态、最少人数、超时及按群划分的当前对局；点击“编辑规则”修改。对局卡展示公开状态、编号、轮次、参与者、当前行动位、公开叫骰和截止时间，不展示私骰。

每局提供确认式“强制结束”。结束请求核对群、玩法、对局 ID 和配置版本，避免误结束其他群或后来新开的对局。新超时设置不改写已有截止时间，从之后的行动阶段生效。

## 5. 真心换真心

### 5.1 群内轮流问答

基本流程：

```text
/真心换真心 → /加入 → /开始 → 按编号提问、其他参与者回答 → 一轮结束 → /继续 或 /结束游戏
```

- `/问 内容`、`/问吧 内容`、`/问题 内容` 用于提问。
- `/真心 内容`、`/答 内容`、`/回答 内容` 用于回答。早期提交提过拼音别名，但当前路由未见相应入口，不作为现有可用指令列出。
- 提问跳过与回答拒答分别记录，不混淆两种操作。
- 系统不评判答案对错，也不附带大冒险。
- 每位参与者依序提问，当前问题收集完毕后展示摘要并轮转。
- 支持中途加入与退出：新成员加入轮转末尾，免答加入时正在收集的问题；退出不删除既有问答记录。
- `/当前游戏` 展示轮次、名单和回答进度，`/真心换真心数据` 提供统计。
- 保留问答统计，移除了不适合顺序问答玩法的轮末、终局排行榜。

### 5.2 按整局计数

`/继续` 仍属于同一整局。至少完整结算一轮后，在整局结束时对有效参与者计一次，相关部门局数津贴也采用整局口径。

没有完整完成任何一轮即强制收局不计有效整局；重复结束或重复处理不会再次计数。此前方案中的“每轮计一局”已经被当前整局规则替代。

### 5.3 后台配置与当前对局

| 参数 | 默认值 | 范围 |
| --- | --- | --- |
| 开启玩法 | 开启 | 开启／关闭 |
| 最少开局人数 | 2 人 | 2–10 人 |
| 提问超时 | 300 秒 | 30–3600 秒 |
| 回答超时 | 600 秒 | 30–3600 秒 |

升级保留原来的最少人数和超时时间。参数统一对各群生效，`/开始`、`/继续` 按当前最少人数检查；关闭只禁止创建新的报名局。

状态页与规则弹窗采用大话骰子同类交互。当前对局公开轮次、状态、参与者、当前提问者、回答进度和截止时间，不展示问答内容。提供带确认、身份与版本检查的强制结束按钮。

详细规则见 [大话骰子与真心换真心后台管理](dice-truth-admin.md)。

## 6. 部门津贴、拉新与风纪罚款

### 6.1 津贴类型与封顶

部门通过后台选择津贴类型，同一类型可以绑定到相应部门。未绑定或停用部门不会发放对应津贴。

| 类型 | 触发方式 | 当前能力 |
| --- | --- | --- |
| 打卡 | 成功打卡 | 发放配置的部门打卡奖励 |
| 事件／演出 | 随机事件、公演有效完成 | 按有效参与者发放配置奖励 |
| 游戏开局 | 真正开局，不是只创建报名局 | 给发起人发放配置奖励 |
| 游戏参与 | 完成规定数量的有效整局 | 按步长发放配置奖励，默认每满 5 局一次 |
| 投稿 | 随机事件投稿审核通过 | 发放部门投稿奖励 |
| 水群 | 符合资格的普通聊天 | 按概率掉落，默认命中率 10%，默认冷却 0 秒 |
| 拉新 | 平台入群系统消息完成邀请归因 | 发给符合部门绑定条件的邀请人 |
| 执法权 | 部门绑定 `discipline` | 授予罚款操作资格，本身不是一笔津贴 |

默认每人每天部门津贴合计上限 5 摸鱼币，可配置。单笔实发取“应发金额”和“剩余额度”的较小值；已满额度不继续入账。罚款抽成也共享该额度。

到账消息优先发送到触发动作所在群：打卡使用消息群，游戏使用对局群，没有群上下文的场景采用私聊兜底。通知包含实发金额及当日累计／上限。

`/我的津贴` 展示当天按类型汇总的明细、合计和封顶状态；`/部门` 展示部门绑定的津贴说明。后台可配置面额、游戏步长、水群概率、冷却、拉新奖励和每日上限。

### 6.2 拉新自动归因

新增解析平台“某人通过某人的链接加入群聊”系统消息的链路，识别邀请人与新人并记录归因；没有邀请人信息的消息不凭空推断。

处理链路为：平台系统消息 → 入站传输保留类型和 metadata → Worker 主循环查询成员目录并解析用户身份 → Core 记录归因与发奖。

修复了两类问题：在 Socket 回调线程直接使用 Playwright 导致线程异常；传输时丢失类型和 metadata 导致归因信息未到达 Core。

平台消息 ID 防止消息重放，新人身份防止重复入群刷同一拉新奖励；无资格、额度不足或解析失败保留相应结果，不能把每条入群消息都当作成功发奖。

### 6.3 风纪罚款

- `/罚款` 和 `/罚` 支持点名或回复目标消息，附言作为理由。
- 执法权由部门津贴类型 `discipline` 绑定，不再依赖独立“执法部门”勾选框。
- 后台配置罚款金额、职级次数配额、冷却及抽成比例。
- 禁止罚自己、执法部门成员及未入职目标。
- 罚款按实际可扣余额执行；执法者按实扣金额获得抽成，默认 20%，向下取整并受部门津贴上限限制。
- `/我的罚款` 支持查询记录；后台可以查看和撤销罚款。
- 撤销返还罚款金额，但不自动追回已经发给执法者的抽成。
- 扣款、退款和抽成有独立流水来源，保留操作记录。

## 7. 物品与商店

### 7.1 分类、限购与商品概览

商品增加分类和每日限购。相同分类共用每日购买额度，没有分类时按商品处理；分类限购桶迁移兼容旧系统商品，保留当日已购连续性。

`/商店` 按分类展示。后台分类改为 Tab，商品列表以名称、状态及关键概览为主，点击“详情”或“编辑”才展开完整参数；搜索、分页和分类筛选继续可用。

### 7.2 商品编辑与效果

支持名称、描述、价格、库存、上架状态、分类、限购、最低职位和效果配置；系统商品同样可以编辑已支持的效果，但保留系统标识。

| 效果类型 | 配置要点 |
| --- | --- |
| 无效果 | 不配置其他效果参数 |
| 赠送币 | 固定赠送金额 |
| 随机奖励 | 最小、最大金额 |
| 对话次数卡／多人游戏次数卡 | 增加次数 |
| 自愿场景公告 | 沿用原有场景收集流程 |
| 授权场景 | 匹配场景模板和受邀人数 |
| 临时状态 | 匹配场景模板与持续时间 |

软删除保留商品编号、系统标识及历史；恢复沿用原编号并默认下架。已删除系统商品不会因初始化自动重新生成。

未使用的背包商品在下次使用时采用当前效果；已经开始的流程使用当次快照。购买、使用记录保存发生时的名称和配置，后续改名不会重写这些快照。

### 7.3 Excel 导入导出

- 下载模板、导出全部商品、上传 `.xlsx` 预览、确认整批操作。
- 导出不受当前搜索和分页限制，可选择包含已删除商品。
- Excel 行支持新增、更新、删除、恢复、跳过；从文件删掉一行不等于删除数据库商品。
- 支持批量改名，包括两件商品交换名称；商品名称在包含已删除商品的目录中仍须唯一。
- 上传后返回文件级或行级错误，行级错误包含工作表、真实行号、列名、原值、原因和修改建议。
- 提供错误报告，保留原商品行并标出错误单元格，修正后可再次上传。
- 预览展示变更前后差异、操作数量、持有数量和未完成流程等信息。
- 删除、恢复及效果修改要求超级管理员权限，并确认风险提示。
- 库存默认不覆盖，只有明确开启同步并确认后才使用文件库存。
- 预览批次绑定管理员，30 分钟有效；确认时复查权限、版本、库存和删除保护。
- 有背包存量、未完成流程、活动状态或可重试任务的商品不能直接删除，应先下架处理。
- 整批使用事务，失败整批回滚；重复确认返回已执行结果，不重复新增或重复写审计。

文件仅支持不超过 5MB、2000 行的 `.xlsx`，不计算公式，拒绝公式单元格、Excel 错误值及不安全文件内容。商品 ID、系统标识、版本等字段属于只读信息；导出文件不能直接充当另一数据库的恢复备份。

详细说明见 [商品 Excel 导入导出与管理](shop-excel-management.md)。

## 8. 凿、发情值与人气榜

### 8.1 指令、目标与连续凿

| 操作 | 示例 |

| 点名连续凿 | `/凿 糯糯 5` |

连续凿默认关闭，由后台开关启用；没有次数参数按一次。指令解析目前把次数限制在 1–50：小于 1 按 1，大于 50 按 50，属于自动截断处理。

回复形态优先使用被回复者身份；点名按注册名、平台昵称等解析，重名提示工号消歧。增加自我目标、群体目标、机器人目标等保护，修复回复机器人消息时误报“未入职”的问题。

当前机器人目标保护采用指定账号识别和回复消息身份检查；历史上增加过后台 `users.is_bot` 配置，但已回退，不属于现有后台功能。

### 8.2 扣发币概率、关联与固定金额

| 配置 | 默认行为 |
| --- | --- |
| 被凿者获得摸鱼币概率 | 0／1／2 币分别为 50%／30%／20% |
| 凿者扣除摸鱼币概率 | 0／1／2 币分别为 50%／30%／20% |
| 扣发币关联 | 开启 |
| 凿者固定扣币 | 关闭；启用后配置 0–99999 币 |
| 被凿者固定发币 | 关闭；启用后配置 0–99999 币 |

双方都采用随机且开启关联时，使用被凿者发币概率与同一次抽样，单次扣币和发币相同。关闭关联后，两方各按自己的概率独立抽样，各组概率须合计 100%。发情值独立于币额。

普通凿击路径中，启用固定金额的一方不再随机计算币额，固定 0 也有效；若一方固定，另一方按自己的固定配置或独立概率计算。关闭固定金额恢复概率设置。

成功抽到 0 币仍计算成功次数；拒绝、冷却或额度耗尽等未成功操作不扣发币。扣币、发币、状态和凿击记录在同一事务内处理，消息重复不会重复结算。凿扣币沿用允许负余额的经济规则，历史记录不补扣。

**已知实现边界：暴击分支目前直接调用随机发币函数，未统一应用被凿者固定发币金额。** 因此“固定发币覆盖所有凿击”在暴击发生时尚不完整；本次整理仅记录此边界，没有修改或重新部署。

### 8.3 职级配额与被凿限制

凿者额度按后台职级配额计算，显式配置优先；无显式配置时，默认 LV1–LV10 每日分别 1–10 次，董事会及以上默认 20 次，无职级按不限处理。统计按群、按北京时间自然日计算。

连续凿超过剩余凿者配额时，当前实现截断到剩余额度；目标每日被凿上限可设为 0–999，默认 0 表示不限，连续过程中达到上限停止，并显示实际执行次数和停止提示。

旧说明中的“凿者统一每日上限默认不限”已被后续职级配额机制替代，不能与当前规则混用。

### 8.4 发情值、暴击与生成文案

- 发情值默认以 0／1／2 增量随机累积；每天不清零。
- 默认 10% 概率触发特殊命中／暴击，该次发情值增量为配置值，默认 10；当前实现为替代普通增量，不是普通增量再加 10。
- 概率、增量和高潮阈值由后台配置，阈值默认 100。
- 达到阈值后发情值清零，累计高潮次数增加；仅“今日高潮次数”跨日重置。
- 生成文案区分档案性别，主角为被凿者，允许最后凿者参与叙述；输出合并为一段。
- 生成链路增加素材多样性、输出检查、超时和失败兜底，降低空回复及截断问题。
- 性别显式设置优先，平台性别同步只回填未知档案，不覆盖用户已设置的性别。

### 8.5 我的凿与人气榜

`/我的凿` 展示当前发情值、今日和累计被凿次数、今日和累计凿人次数、高潮次数及接受状态。旧 `/我的发情值` 兼容映射到该查询。

`/人气榜` 按本群当天成功被凿次数取前 5，不按发情值或高潮次数排名；旧 `/发情值排名`、`/最受欢迎` 等入口映射到当前榜单。

定时公告跟随收益榜配置，默认 12:00、16:00、20:00、23:59。每群每天每时段仅处理一次，接收群须开启监听和公告。没有收益不阻止人气榜发送。


### 10.3 游戏统计与关键公式

“超级游戏王”支持国王、大话骰子、真心换真心、德州扑克、甩锅炸弹、蹦蹦数字炸弹、谁是卧底、我有你没有、躲猫猫、记忆考核、记忆考核公会赛，共 11 类游戏。

```text
整局去重键 = 游戏类型 + 游戏 ID + 员工 ID
周参与次数 = 本周结束的有效整局参与记录数

德州扑克单局净额 = 最终筹码 - 原始买入
德州扑克周净额 = 当周有效牌局的单局净额之和
赌圣成绩 = max(周净额, 0)
扫把星成绩 = max(-周净额, 0)
```

整局多轮仍只计一次；只报名、取消、未实际参与或没有有效轮次的不计。国王和数字炸弹的受罚／胜出称号按已揭晓或结算轮次统计，周归属不必等待整局结束。

数字炸弹普通局和积分赛都纳入极品抖 M、摸鱼幸运星；仅计实际报数且有效结算的轮次，跳过和退赛扣分不计受罚，并列符合者分别计一次。

国王、骰子和真心换真心按有效轮次识别整局参与者。公会赛计完成轮次的上场选手，候补不计。红包、彩票、随机事件、公演不是整局游戏。

### 10.5 两次公告与后台管理

每周结算完成公布一次，周一配置时刻再公布一次，默认 09:00；两种公告各自去重。记录表示入队，不等于群成员一定已经收到，实际发送还受通道和队列状态影响。

后台入口为“人员与系统 → 称号与荣誉”。普通管理员查看配置、预览、周期、历史及员工获奖记录；超级管理员可保存配置、确认结算和纠错。

可配项包括总开关、统计群、公告开关与群、再次公布时间、各称号启停、名称、门槛、展示排序、是否公开成绩及说明。新初始化总开关默认关闭，公告默认开启。

常规配置从下一统计周生效，本周保留原快照。多个统计群合并评选，不为每个群各发一套。打卡和投稿使用公司记录，聊天、凿、游戏、AI 等使用所选群范围。

后台预览可补齐统一游戏参与表，不能理解成完全无写入；预览本身不发奖。确认结算核对预览摘要，规则或数据变化时要求重新预览。

纠错只能选择原快照中具备资格的员工，需原因及修订号；保留前后结果、操作者和审计，不延长有效期，不自动重发已经入队的公告。打卡正常结算直接授予所有达标者，当前纠错页面不提供任意追加多人获奖行。

完整统计口径、边界及计算示例见 [荣誉称号系统详细说明](honor-system.md)。

### 13.2 不能视为全仓全通过

此前扩展回归结果为 312 通过、5 失败，已记录的失败分别涉及一个打卡奖励期望、Windows 文件权限断言，以及三个旧迁移测试的精简 fixture 缺少 `departments` 表。这些不能用专项通过结果掩盖，也未顺手修改无关实现。

历史分支总结中的“全仓 1768 用例”属于旧版本记录，本次没有重新统计或完整运行全仓，因此不作为当前通过数量。

另有以下行为需要使用时区分：

1. 固定发币在凿暴击分支存在第 8.2 节记录的边界。
2. 连续凿次数目前自动截断，不是所有超限输入都会先拒绝执行。
3. 人气榜和荣誉公告时间均依赖任务轮询及服务运行，不是平台层面的准时送达保证。
4. 荣誉预览补齐游戏参与记录，但不发奖、不补发旧津贴。
5. 荣誉、生日新初始化默认开关与生产已经保存的开关不是同一回事；生产应查看实际配置。
6. 旧 `rule.md` 和早期 `.trae` 方案中，部分单时刻生日、凿者统一限制、按轮计局表述已过期，本说明按当前实现整理。
