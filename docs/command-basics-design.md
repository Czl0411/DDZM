# 基础群玩法指令设计

## 目标

为“摸鱼公司群”提供第一批可持久化的玩法指令，并在管理端提供对应的数据入口。机器人以“美女总监事”的轻松口吻回复，但不模拟传统公司工作流程。

## 已确认规则

- 时间规则统一使用 `Asia/Shanghai`（北京时间）：所有业务时间在应用接口、管理端与业务判断中均以北京时间读写和展示；打卡按北京时间自然日结算。数据库继续使用带时区时间类型，避免失去时间点语义。
- `/入职 小明` 创建员工，初始余额为 `0` 摸鱼币。
- `/打卡` 每个北京时间自然日只能成功一次，每次获得 `5` 摸鱼币。
- `/余额` 显示当前摸鱼币余额。
- `/我的物品` 显示员工持有物品。
- `/商店` 首版仅展示上架商品；购买语法不在本次范围内。

## 数据与行为

- `command_definitions`：指令、说明、启用状态；初始化上述五项。
- `users`：平台用户 ID、昵称、余额、入职时间。
- `daily_checkins`：用户与北京时间日期唯一，用于防重复打卡。
- `items`：可上架物品的名称、描述、价格、库存和状态。
- `user_items`：用户持有的物品数量。

入站消息只在匹配且启用的指令时生成回复。指令效果在同一数据库事务内执行，重复平台消息仍由既有入站幂等机制拦截。

## 管理端

左侧导航提供：运行概览、指令库、员工、物品与商店。首版各页面展示真实数据库数据；指令库支持启用和停用，物品与商店展示上架数据。

## 非目标

- 不实现购买、赠送、排行榜或复杂经济系统。
- 不提供可执行脚本式的数据库指令逻辑。
- 不改变既有浏览器登录、监听和出站队列机制。
