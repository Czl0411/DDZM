# 装备商城（第一版）

装备商城与原 `/商店` 独立：单独的目录、编号、装备库和购买记录。仅共用员工身份、摸鱼币余额及余额流水。装备按员工账号跨群共享，购买必须在已启用的群内执行。

## 指令

| 指令 | 用途 |
| --- | --- |
| `/装备商城`（也支持 `/装备商店`） | 查看已上架装备、独立编号、价格、预计日收入及持有状态 |
| `/购买装备 编号` | 扣除摸鱼币并永久获得装备；每件限购一次，不自动装备 |
| `/装备 编号` | 装备已购买物品 |
| `/卸下 编号` | 卸下并保留所有权，不退款 |
| `/我的装备` | 查看自己的装备库和装卸状态 |
| `/我的工位` | 在群里获取自己的工位链接，点击查看装备组合和预计日收入 |
| `/帮助 装备商城` | 查看以上用法 |

装备编号与原商品编号属于两个独立目录，即使同为 #1 也代表不同商品。原 `/购买`、`/使用`、`/我的物品` 不处理工位装备。

## 规则及数据

- 初始无已购装备，购买后手动装备。每件装备最多拥有一份；装卸不会消耗或重复购买。
- 预计日收入是当前所有已装备物品的 `daily_income` 之和。未装备不计入。全套为 14 摸鱼币/日。
- 第一版只展示预计收入，尚未启用自动结算或发币；不涉及小游戏成长、XP 或舒适度。
- 同一入站消息成功购买后重放会返回首次购买结果，避免重复扣款。不同消息再次购买同件装备会提示已拥有。
- 扣款、余额流水、所有权和购买记录在同一事务内完成；失败整体回滚。购买记录保存实际成交价格及首次结果。
- 余额流水来源为 `equipment_purchase`（装备商城购买）。不套用原商店的生日折扣、库存和每日限购规则。
- 下架仅阻止新购买，已购装备仍可查看、装卸及参与预计收入计算。
- 目录初始化只补缺失记录，不覆盖已有名称、价格、收益或上下架状态。

新增表：`equipment_items`、`equipment_ownerships`、`equipment_purchases`。新增迁移：`20261015_104`，承接 `20261012_103`。迁移只创建独立装备表及默认目录，不改动原商品、持有物品和历史购买记录。

后台现有指令库可分别启停六个指令，`/装备商店` 别名服从 `/装备商城` 的开关。此版尚未添加专门的装备商品编辑页、群内图片回复和收益结算。

## 群内工位链接

在已启用的群内发送 `/我的工位`，机器人回复员工名称和可点击的个人链接，例如：

```text
【糯糯的工位】
点击链接查看工位：
https://workstation.example.com/workstation/<个人只读签名>
已装备：主显示器、机械键盘
预计工位日收入：3 摸鱼币（自动结算尚未启用）。
装备库和工位状态跨群共享。发送 /我的装备 管理。
```

- 网页读取数据库中的真实员工名称、已装备物品和当前收益参数，不使用演示页的浏览器购买记录。已购买但未装备的物品不会出现在工位中。
- 购买、装卸继续使用群指令；操作后点击网页“刷新工位”即可读取最新状态。新员工显示无装备工位。
- 这是分享用的只读页面，任何拿到链接的人都可查看该工位；链接不能用于购买、换装、扣币、发币或登录后台。页面不展示余额、平台账号、生日和管理密钥。
- 个人签名使用内部员工 UUID 与专用用途的 HMAC-SHA256 校验，签名密钥复用服务端 `DZMM_CORE_TOKEN`，不会发送给浏览器。链接没有自动过期时间；更换 core token 会使旧链接失效，重新发送指令可获得新链接。更换 token 时也须同步各内部调用服务的现有配置。
- 基底保留原有其他桌面物件，10 件核心装备使用独立 PNG 图层；遮挡、轮廓和阴影仍是美术草稿。打包资源经过无损显示优化，合成效果和原有素材一致。
- 原 `docs/workstation-game-demo.html` 继续保留为独立演示，不代表真实账户数据。本次提供普通网页链接，未创建或发布平台游戏卡。

### 配置与访问入口

新增环境配置（示例域名须替换为实际可访问地址）：

```dotenv
DZMM_WORKSTATION_PUBLIC_URL=https://workstation.example.com
```

这里填写网页服务的公开基址，不包括 `/workstation`、员工编号或签名。也支持带反向代理前缀，例如 `https://example.com/games`。仅本机预览可使用 `http://127.0.0.1:8766`，不要把本机地址配置成群友使用的地址。

未配置时 `/我的工位` 明确提示“工位网页暂未开放，请管理员配置公开访问地址”，并保留文字概览，不会自动猜测公网 IP。该配置由 core 服务读取，正式部署时应写入既有 root-only 的 `/etc/dzmm/dzmm.env`。

页面由现有 admin-web 服务提供，但这些展示路由无需管理员登录：

| 公开路径 | 用途 |
| --- | --- |
| `/workstation/<个人只读签名>` | 工位网页 |
| `/api/workstations/<个人只读签名>` | 只读装备快照 |
| `/static/workstation.js`、`/static/workstation.css` | 展示脚本与样式 |
| `/static/workstation/*.png` | 底图与允许访问的装备图层 |

公网反向代理只需把上述路径转发到 admin-web。如果使用 `/games` 等前缀，应转发时去掉此前缀。保持 core 内部接口仅回环访问，不要将 `/internal` 暴露到公网，也不要把管理员或集成 API token 放入链接。建议公网使用 HTTPS。

网页、脚本、样式及 11 张图片已纳入安装包，无需服务器保留 `docs` 目录。这个链接功能没有增加额外数据库表或迁移；仍需先应用装备商城迁移 `20261015_104`。

## 验证和交付范围

### 工位大厅与图片保存

`/我的工位` 的链接作为单独一条普通群消息直接发送，内容仅为URL，不引用原指令消息；前一条工位说明仍单独发送。消息仍关联原入站记录以保持去重，重复接收同一条指令不会重复发链接。

平台游戏进入后默认展示工位大厅，按工号排序，包含未购买装备的员工；每页24人，可以按名字或工号搜索。“我的工位”进入当前登录员工自己的工位，点击卡片查看其他员工，“返回大厅”保留原搜索和页码。

大厅只展示名字、工号、已装备物品和预计收入等工位信息，不提供平台账号ID、余额、生日等私人档案。查看他人工位不会获得购买、装卸或代发图片的权限。原有个人签名链接仍直接进入只读详情。

详情保留平铺布局切换、工号和本人发送图片到群里的操作，并增加“下载图片”。完整PNG为1536×1024，按实际装备合成，保留底图及非装备桌面物件。普通网页打开保存窗口后可点击下载；DZMM当前游戏沙箱不允许直接下载，窗口展示完整原图，电脑右键“图片另存为”，手机长按保存（以客户端支持为准）。不会把生成预览误报为已下载。

图片生成与保存不产生群消息、不扣币。平台图片从经过身份验证的后端按真实装备合成，避免沙箱跨域图片污染画布；原图请求等待上限为90秒，普通接口保持20秒，超时显示中文提示。无须数据库迁移、新密钥或修改玩法。2026-10-15 大厅与链接直发更新已部署，平台游戏版本 `07b9c2a` 已发布；发布记录和回退备份见 `docs/gamefy-workstation-publishing.md`。

测试覆盖独立目录、购买扣款、跨群装卸、重复消息、余额不足、非法参数、私聊拦截、停用指令、下架后持有保留、配置保留、事务回滚及迁移升降级。

工位链接新增验证包括：群内回复个人链接、未配置时提示、真实装备状态读取、买后未装备不展示、装卸后刷新、不同员工隔离、链接篡改与未知员工返回 404、上游故障返回友好 503、只读接口不可修改、链接不能充当后台密钥、下架装备保留展示，以及公开读取不会补写装备目录。

本次验证结果：

- 装备商城、原商店、商品管理、群指令及服务回归共 242 项通过，其中包含本次新增迁移的升降级验证。
- 扩展的完整迁移测试集在 UTF-8 模式下为 45 项通过、56 项失败。将升级目标限制为本次变更前的 `20261012_103` 后，原有测试集为 44 项通过、56 项失败，失败用例名单完全相同。
- 这些遗留失败涉及旧迁移测试数据库缺少 `memory_assessment_settings`、`company_lottery_settings` 等表或字段，本次没有改动相关旧迁移。
- 本次数据库运行验证使用 SQLite 临时库；未连接生产 PostgreSQL，也未进行 PostgreSQL 并发压力验证。
- 工位链接扩展回归首次为 542 项通过、2 项失败。其中一项是新增装备指令未补入既有测试的完整指令清单，现已修正并单独复测通过；另一项是既有档案图片上传测试断言 Unix 目录权限 `0700`，Windows 无法满足该断言，未修改无关实现。
- 修正后，工位链接、URL 配置校验、指令清单和 core 生产入口的针对性复测共 40 项通过。其他生产入口测试还受本机缺少 `psycopg` 和 Windows 不支持 `os.getpgid` 限制，未声称完整运行通过。
- 桌面 1280px 与手机 390px 浏览器预览均已检查，没有横向溢出；正确显示 3 件实际装备、预计 5 摸鱼币/日，并验证了另一员工无装备时的初始页面。
- Python 安装包构建成功，并检查包含工位页面、脚本、样式、后端模块及全部 11 张 PNG；原始 `docs` 素材没有被覆盖。

本次仅写代码并在临时测试数据库验证；没有迁移生产数据库、部署、提交或推送。

- 页面显示员工真实工号，格式与 `/我` 一致，例如 `#0001`。
- “平铺布局”切换为上方完整工位图片、下方平铺信息卡；可通过“侧栏布局”切回。平台游戏方向需设为横屏，避免宿主竖屏框把页面挤窄。

- 目标群来自本人最近24小时发送过 `/我的工位` 的已启用群，多个群可选；没有目标群时提示先回群发送指令。每名员工每分钟最多提交一次；同一请求重复提交不会重复发送。
