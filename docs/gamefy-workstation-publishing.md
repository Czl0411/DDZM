# 工位养成接入 Gamefy 与发布说明

## 当前版本

游戏卡片 ID：`3772306`；平台验签使用的独立游戏 UUID：`8c0c9601-1a72-42f7-b379-120adf63886d`。两者不能混用。本地工程为 `gamefy-workstation/`，入口是 `publish/index.html`。

这一版复用已有工位画面和 11 张图片：初始工位没有核心装备，杯子、植物、笔记本等桌面物件保留；购买并装备后按独立 PNG 图层组合。素材的遮挡、阴影与轮廓仍是美术草稿。

购买与装卸继续在群内执行 `/装备商城`、`/购买装备 编号`、`/装备 编号`、`/卸下 编号`。网页只展示工位、装备清单及预计收入，不执行购买、扣币、发币，也不增加小游戏成长系统。自动收益结算尚未实现。

### 两种运行模式

- **素材预览**：`publish/config.js` 的 `apiBaseUrl` 为空时生效。默认无装备，可选择三件装备或全套十件装备。页面明确标注演示数据，切换不会修改数据库。
- **真实工位**：填写可访问的 HTTPS 后端基址后生效。页面通过 `dzmm.user.info()` 获取当前玩家 JWT，后端验证身份后返回该玩家的实际装备。刷新会重新获取 JWT，支持已过期身份更新。未登录、没有员工档案、验签失败或网络故障时显示对应提示，不自动降级成演示装备。

## 本地构建和压缩包

在仓库根目录执行：

```powershell
python scripts/build_gamefy_workstation.py
```

构建会从现有 admin 静态目录复制共用样式、渲染脚本和图片，保留原素材。生成文件已经在 Gamefy 工程自己的 `.gitignore` 中排除，不需要重复维护两份图片源码。

导入包：`output/gamefy-workstation-preview.zip`。压缩包只包含 `dzmm.json` 和 `publish/` 的静态文件，不包含 Python 源码、数据库、环境配置、用户数据和密钥。`functions/` 当前为空，本版不使用平台服务端函数。

构建检查包括：入口、ASCII 文件名、相对资源引用、单文件 25 MiB / 总量 100 MiB / 3000 文件限制、常见凭证格式，以及沙箱不支持的浏览器存储。

准备正式发布时执行：

```powershell
python scripts/build_gamefy_workstation.py --release
```

这个选项要求配置 HTTPS 数据后端，防止把未连接真实数据的预览包误当作正式候选版本。它只做静态检查，不证明该后端已部署或健康。

## 服务端准备

1. 安装项目依赖，新增 `PyJWT[crypto]>=2.10,<3`，用于标准 RS256 JWT 验签。
2. 按既有流程应用装备商城迁移 `20261015_104`。Gamefy 接入没有新增数据表，不复制或重置真实员工数据。
3. 在服务器已有 root-only 环境文件 `/etc/dzmm/dzmm.env` 配置：

   ```dotenv
   DZMM_GAMEFY_GAME_ID=8c0c9601-1a72-42f7-b379-120adf63886d
   ```

   未配置时平台接口返回 503，不允许跳过验签。普通签名工位链接继续使用现有 `DZMM_WORKSTATION_PUBLIC_URL`，该设置不会自动切换 `/我的工位` 的回复入口。

4. 使用自己的 HTTPS 域名，将 **`/api/gamefy/workstation`** 转发给 admin-web。支持域名前缀，例如外部 `/games/api/gamefy/workstation` 映射到内部同名接口，去掉 `/games` 即可。
5. 保持 `/internal` 接口仅本机可访问；不要将 core 服务直接暴露到公网。反向代理要保留 `Authorization` 请求头，并支持 OPTIONS。日志不要记录该请求头；可在代理层为工位接口配置合理限流。
6. 重启服务后验证健康。沿用既有部署约定：部署命令整体使用 `sudo bash`；单独重启 core 后，对 `dzmm-browser-worker`、`dzmm-ai-worker`、`dzmm-ai-memory-worker` 执行 `reset-failed` 和 `start`，再确认五个服务状态。此文档不代表已执行部署。

### 身份与权限

前端调用公开接口：

```text
GET https://workstation.example.com/api/gamefy/workstation
Authorization: Bearer <dzmm.user.info() 返回的短期 JWT>
```

后端固定从官方端点获取公钥：

```text
https://www.dzmm.ai/api/gamefy/.well-known/jwks.json
```

严格验证算法 `RS256`、签名、`issuer=dzmm-gamefy`、`audience=8c0c9601-1a72-42f7-b379-120adf63886d`、有效期、签发时间和 UUID 格式的 `sub`。公钥由标准库缓存一小时。只按验签后的 `sub` 匹配既有员工 `platform_id`，不信任前端用户 ID、昵称或分享参数 `gp`。

`DZMM_GAMEFY_GAME_ID` 必须与平台签发 JWT 的 `aud` 一致，不能直接复制工坊网址中的卡片编号。新建游戏需要重新核对自己的游戏 UUID。公钥请求显式携带 `User-Agent: DDZM-Workstation/1.0` 和 `Accept: application/json`，避免默认 Python 请求被上游拒绝；所有 HTTPS 校验与 JWT 验签保持启用。身份失败日志只保留错误类别和受众校验错误，不记录 token 或个人资料。

返回内容仅含员工显示名、已装备项目、预计收入、货币名及结算开关；不包含余额、平台 ID、生日、管理密钥或个人签名链接。

Gamefy iframe 没有 `allow-same-origin`，请求来源可以是 `Origin: null`。仅工位专用接口开放 `Access-Control-Allow-Origin: *`，允许 `Authorization`、`Content-Type` 的 OPTIONS 预检，不允许跨域 Cookie 凭证。身份权限仍由 JWT 控制；其他后台路由不开放跨域。

核心内部路径为 `/internal/gamefy/workstation`，调用必须同时带 core 内部凭证和玩家 JWT。admin-web 负责转发与错误脱敏。购买和装卸不提供网页写入接口；工位图片发送使用下文专用接口。

## 配置前端真实数据地址

修改 `gamefy-workstation/publish/config.js`：

```javascript
window.workstationConfig = Object.freeze({
  apiBaseUrl: "https://workstation.example.com",
});
```

替换为实际域名；这里仅填基址，不加 `/api/gamefy/workstation`。如果有前缀则填 `https://example.com/games`。前端会拒绝 HTTP、含用户名密码、查询串或片段的地址。

该配置是公开信息，**不能填写开发者密钥、Bot token、core token、admin token、集成 API key 或数据库地址**。玩家 JWT 仅在内存中用于当前请求，不写入浏览器存储、KV、页面或日志。

## 正式发布与上架

发布前需要满足：已登录、VIP1 以上、拥有该游戏、代码保存完成、没有并行发布、真实数据接口可访问。

按顺序完成：

1. 服务端部署与 HTTPS 检查。
2. 在工坊用真实账号预览；检查本人身份匹配、无档案提示、群内装卸后的刷新，以及不同账号隔离。
3. 补充游戏名称、头像 / 封面、简介和作者说明。推荐名称“摸鱼公司 · 我的工位”，简介说明群内购买、网页查看和收益尚未自动结算。
4. 点击工坊“发布”，确认静态版本发布成功。
5. 到游戏详情页提交上架审核；审核通过后普通玩家才能进入。
6. 用平台实际生成的分享链接验证普通玩家访问，再配置 `DZMM_WORKSTATION_GAME_URL`，将 `/我的工位` 的群回复入口切换到游戏链接。未配置时继续回复个人只读网页链接。

“保存代码”“发布游戏版本”“提交上架审核”是三个独立动作。只有本地构建成功不代表游戏已上线；发布代码成功也不代表通过上架审核。

工坊“游戏信息 → 游戏方向”应设置为横屏。页面内“平铺布局”只调整自身布局，不能改变宿主 iframe 的竖屏比例。

工位读取新增 `employee_number` 和本人可发送的 `share_groups`。发送专用接口：

| 方法 | 公开路径 | 用途 |
| --- | --- | --- |
| POST | `/api/gamefy/workstation/share` | JSON 传 `group_id`、随机 UUID `request_id`，提交当前工位图片 |
| GET | `/api/gamefy/workstation/shares/{request_id}` | 查询本人这次发送的状态 |

两者均要求平台玩家 JWT，并由 admin-web 携内部凭证代理至同名 `/internal/gamefy/workstation/...` 路径。禁止网页指定员工、图片 URL 或装备快照。目标群只接受本人最近24小时发过 `/我的工位` 且仍启用的群，不允许任意群转发；每人每分钟最多一次，同一请求编号幂等。多个群在页面中明确选择。

合成在 browser worker 中按与网页一致的图层顺序执行，底图和非装备桌面物件保持不变，再经既有上传接口和群消息通道发送。队列存储发送时的真实装备快照，后续装卸不改变已经提交的图片。页面仅在队列状态变成 `sent` 时提示成功；排队超时会提示到目标群查看。个人签名展示页仍只读。
