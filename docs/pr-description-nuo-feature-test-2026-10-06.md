# PR 标题

feat: 完善群聊玩法与周荣誉系统，重构管理后台及商品批量管理

# PR 说明

本分支补齐生日、部门津贴、风纪罚款、大话骰子、真心换真心、凿与人气榜等业务，新增按周结算的荣誉称号与统一游戏参与统计，并调整管理后台的展示和编辑流程。商品支持 Excel 批量管理，外部系统可通过独立鉴权接口查询员工、余额、游戏额度及发扣币。

来源分支：`niuerhaizaishan/DDZM:nuo/feature-test`；功能代码提交：`5c66d7f`。本说明按相对上游 `Czl0411/DDZM` 的本地 `origin/main` 共同祖先 `4a65a640` 整理，包含生日功能；若目标是 fork 的 `main`，其中已合入的生日更新不重复计入 PR 差异。正式创建 PR 时，以选定目标分支的实际 diff 为准。

## 主要更新

### 1. 荣誉称号与统一游戏统计

- 新增 29 项荣誉称号，覆盖打卡、聊天、随机事件、公演、投稿、游戏、凿与 AI 互动。
- 按北京时间周一至下一周周一统计；排名类称号每项最多一人，无合格者空缺，同分按规则抽签；打卡成就授予所有达标员工。
- 牛马之王要求统计周七天全勤，保留 7 天；牛马之神要求连续 30 天打卡，保留 30 天；牛马之仙要求连续 100 天打卡，保留 100 天。
- 新增荣誉查询、个人称号、佩戴与历史入口；兼容佩戴、装备、编辑称号指令。佩戴后 `/我`、`/me` 在名字后展示 `【荣誉称号：称号名称】`。
- 结算完成公布一次，周一默认 09:00 再次公布；再次公告时间后台可配置，两次公告独立去重。
- 后台支持启停、统计与公告群、名称、门槛、排序、成绩公开、周预览、确认结算、历史及审计纠错；常规规则变更从下一统计周生效。
- 统一记录 11 类游戏的有效整局参与，同一局同一员工只计一次；真心换真心、大话骰子继续多轮不重复累加整局数。
- 极品抖 M、摸鱼幸运星同时纳入国王游戏与蹦蹦数字炸弹对应指标。

### 2. 群聊玩法与经济规则

- 生日：登记与隐私设置、多时刻祝福、年度礼金去重、随礼、生日特权、入职周年及后台试跑与补发。
- 大话骰子：完整叫骰、开骰、多轮、私聊收骰、万能点、跨局战绩与超时处理；后台增加启用开关、最少人数、公开当前对局与强制结束。
- 真心换真心：顺序问答、中途加入退出、问答统计及有效整局计数；后台增加启用开关、最少人数、公开当前对局与强制结束。
- 部门津贴：按部门绑定打卡、游戏、演出、投稿、水群、拉新等奖励；每日总额封顶、到账通知和 `/我的津贴` 明细。
- 拉新：识别平台入群系统消息、解析邀请人并防重复发奖。
- 风纪罚款：执法资格、职级配额、冷却、实际扣款抽成、查询与撤销；`/部门` 的部门增益说明改为“可执行风纪罚款操作，获得罚款20%的奖励”。
- 凿：双方随机扣发币、关联或独立概率、固定金额、默认关闭的连续凿、职级额度、被凿限制、跨日保留发情值及可配置暴击。
- 修复指定机器人账号及回复机器人消息时的目标识别；未知档案性别可回填，显式性别不被同步覆盖。
- 人气榜：按当天成功被凿次数排名，跟随配置时段公告；没有记录时也发送空榜提示，避免看起来漏推送。

### 新增 API Token 的生成、配置与使用

这里的 API Token 指 `DZMM_INTEGRATION_API_KEY`，是管理员生成并配置的随机共享密钥，通过请求头 `X-Api-Key` 传递。当前没有登录换 Token、JWT、后台自动生成或自动过期机制；它与后台 `DZMM_ADMIN_TOKEN`、内部 `DZMM_CORE_TOKEN` 分别独立。

1. 在服务器可信终端生成 32 字节密码学随机 Token（256 位随机强度，URL-safe 编码通常为 43 个字符）：

   ```bash
   python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
   ```

   该命令会在终端显示新 Token。妥善保存到调用方的受限配置或密钥管理工具，不将输出粘贴到 PR、仓库或公开日志。每套环境独立生成，不使用示例值、后台密码或旧历史中的密钥。

2. 编辑服务器环境文件：

   ```bash
   sudoedit /etc/dzmm/dzmm.env
   ```

   增加或替换下面这一项，将占位符替换为刚生成的完整 Token；同名变量仅保留一项，其他配置保持原值：

   ```dotenv
   DZMM_INTEGRATION_API_KEY=<刚生成的完整Token>
   ```

   确认文件权限，并重启管理端使新值生效：

   ```bash
   sudo chown root:root /etc/dzmm/dzmm.env
   sudo chmod 600 /etc/dzmm/dzmm.env
   sudo systemctl restart dzmm-admin-web
   sudo systemctl is-active dzmm-admin-web
   ```

   集成鉴权运行在管理端，单独修改该 Key 只需重启 `dzmm-admin-web`；此步骤没有重启 Core，不需要恢复三个 Worker。若同时修改其他服务使用的凭据，则按各服务依赖关系重启。

3. 调用方在自己的受限环境或密钥管理工具中配置同一个 Token，每次调用携带：

   ```http
   X-Api-Key: <同一个完整Token>
   ```

   本机 API 基地址为 `http://127.0.0.1:18090/api/integration`；跨服务器调用使用实际授权的 HTTPS 入口。不要把 Token 放进 URL 查询参数或浏览器前端代码。

4. 在服务器验证只读余额接口。先把下面的员工 ID 占位符替换为真实有效的 `platform_id`，整体通过 `sudo bash` 读取 root-only 配置；通过标准输入传入请求头，避免把 Token 放进 curl 命令参数：

   ```bash
   sudo bash <<'DZMM_API_CHECK'
   set -euo pipefail
   source /etc/dzmm/dzmm.env
   : "${DZMM_INTEGRATION_API_KEY:?请先配置集成密钥}"
   printf 'X-Api-Key: %s\n' "$DZMM_INTEGRATION_API_KEY" |
     curl -sS --header @- --write-out '\nHTTP %{http_code}\n' \
       'http://127.0.0.1:18090/api/integration/users/<真实员工platform_id>/balance'
   DZMM_API_CHECK
   ```

   正常返回 `200`；员工不存在返回 `404`；缺少或错误 Token 返回 `401`；服务未配置集成 Key 返回 `503`；超过每分钟 60 次限制返回 `429`。该验证只查余额，不发币、不扣币。已有 `scripts/smoke_integration_api.sh` 会实际发扣币，不作为只读验收使用。

轮换时重新生成 Token、替换环境文件、重启管理端并同步全部调用方。当前仅支持一个共享 Key，重启生效后旧 Key 立即失效，没有双 Key 过渡期或每个调用方独立 Key 配置；部署时安排好同步切换。

另需核对环境绑定：`scripts/smoke_game_quota.sh` 含特定员工平台 ID，`scripts/set_nuonuo_heat.sh` 含员工和群 ID，`scripts/set_persona_gender.sh` 及 `scripts/clear_xiaoxiaonuo_allowance.sh` 等面向特定人员的数据脚本需要逐项审查。其中部分脚本会修改或删除数据，不能作为通用部署步骤运行。`src/dzmm_bot/core/repository.py` 的 `_CHOP_BOT_ACCOUNT_NAMES` 使用指定机器人昵称，换账号时也需核对。
