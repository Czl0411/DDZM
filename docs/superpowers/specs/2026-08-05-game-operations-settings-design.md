# 玩法运营配置设计

## 目标

让单个群机器人的运营者能在管理端直观看到并修改基础经济规则，不需要编辑数据库、环境变量或回复模板。

## 范围

新增左侧菜单“玩法配置”，首版包含一张“经济规则”卡片：

- 货币名称，默认“摸鱼币”，用于所有余额、打卡和商店回复；
- 入职初始余额，默认 0，只应用于之后执行 `/入职` 的新员工；
- 每日打卡奖励，默认 5，应用于之后成功执行 `/打卡` 的员工；
- 每日重置说明，固定显示“北京时间 00:00”，不可修改。

商店、员工和指令库继续保留为独立页面。系统默认回复改用可插入的 `{货币}` 变量，因此会跟随货币名称；已经由管理员保存且仍写死“摸鱼币”的自定义模板不自动改写，运营者可按需编辑文案。

## 使用体验

运营者进入“玩法配置”后先看到当前生效的三个数值和其影响范围。点击“编辑经济规则”后，在一个弹窗中修改字段；每个数字字段紧邻展示单位、允许范围和影响说明。保存成功后关闭弹窗、刷新卡片，并在页面底部显示“经济规则已保存”。

弹窗不允许空值、负数、非整数或超出 0–999 的数值；货币名称去除首尾空格后必须为 1–12 个字符。校验错误保留已输入的内容并显示可理解的中文提示。

## 架构

Core 持久化一条单例 `game_settings` 记录并在首次读取时写入默认值。`GroupCommandHandler` 从仓库读取该记录，在创建新员工时使用入职初始余额、在成功打卡时使用打卡奖励，并在动态变量和默认文案中提供货币名称。迁移将未被改动的旧默认模板转换为 `{货币}` 变量，同时保留管理员自定义的模板。

Core 提供读取与更新运营配置的受令牌保护接口。Admin CoreClient 透传接口；Admin 页面新增独立视图与编辑弹窗。现有用户余额、打卡记录、商品价格及已保存回复模板不做数据迁移或追溯修改。

## 数据与时间约束

- 配置为全局单群配置，不新增多群隔离模型。
- 所有时间仍使用 `Asia/Shanghai`；每日打卡唯一键继续使用北京时间日期。
- 设置更新应立即影响下一条新入职或新打卡指令。
- 只有管理员令牌可读取或更新配置。

## 验证

测试覆盖默认设置、字段校验、管理员 API 授权、更新后的新入职余额、更新后的打卡奖励，以及管理端“玩法配置”入口、读取和保存请求。完整测试套件须通过；部署后由运营者使用新设置完成一次 `/入职` 与 `/打卡` 的真实验证。
