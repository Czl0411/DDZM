# 躲猫猫分轮消息设计

## 目标

把躲猫猫的两轮巡查从一条合并回复改为实际排队的独立群消息。

## 用户可见流程

- 第一轮命中：发送一条“第一轮巡查 + 被发现结算”。
- 第一轮未命中：先发送“第一轮巡查 + 奇怪，人躲哪里去了.......”，再发送“第二轮巡查 + 胜负结算”。
- 第二轮仍只在第一轮未命中时发送，且巡查地点保持不重复。

## 出站可靠性

- 一个入站消息可产生一条或多条出站消息。
- 入站消息的唯一约束继续作为命令幂等边界：平台同一消息重试不会重新创建游戏或重复排队巡查消息。
- 移除 `outbound_messages.inbound_message_id` 的唯一约束，并新增 `reply_index`；同一入站产生的消息按照该索引被 Worker 依次领取和发送。
- 随机事件旁观警告与命令回复先组成一个回复列表，再以 0、1、2… 顺序入队，避免同一消息的回复冲突。

## 模板

- 新增“第一轮未命中”和“第一轮发现”两个躲猫猫回复场景。
- 已有“被系统找到”仅用于第二轮发现，“躲藏成功”仅用于第二轮成功。
- 所有场景继续通过管理端的模板弹窗编辑；默认模板提供 `{巡查地点}`、`{惩罚金额}`、`{奖励}`、`{余额}` 等现有变量。
- 已自定义的旧模板不覆盖；数据库迁移只调整完全等于旧默认文案的记录。

## 验收

- `/躲` 第一轮未命中后，对同一入站消息生成两条按 `reply_index` 排序的出站记录。
- 第一条包含第一轮与指定过渡文案，第二条包含第二轮与最终结算。
- 第一轮命中时仅生成一条出站记录与一次惩罚。
- 重复相同入站消息不新增出站记录或再次结算。
