# 随机事件模板、详情记录与今日计划设计

**日期：** 2026-08-06  
**状态：** 已确认，待实施

## 目标

将随机事件的正式剧情从单纯的开场白文本升级为场景下可配置的事件模板；在一场事件运行期间记录参与者发言；使运营者能在今日随机事件列表中看到预定的场景、事件与状态，并对待开始项立即触发或调整时间。

## 数据关系

```
场景
├── 报名公告、席位、奖励、目标轮次
└── 事件模板（一个或多个）
    ├── 名称
    └── 开场白

当天计划 → 预先选定场景和事件模板
运行中的事件 → 冻结场景名、事件名、开场白、详情发言列表
```

事件模板中的开场白继续支持角色变量，例如 `{主持}`。事件满员时，变量替换为所选角色对应的真实玩家昵称；同角色多人按加入顺序用 `、` 连接。

## 配置与迁移

- 管理端的场景编辑弹窗将“正式剧情开场白”改为事件模板列表。
- 每个模板必须有非空名称和非空开场白。
- 现有开场白迁移为同场景下的事件模板，名称为“未命名事件”，保证既有配置可继续运行。
- 场景列表显示事件模板数量；正式开场白变量按钮继续仅对开场白生效。

## 每日计划与触发

- 每日北京时间 00:00 生成计划时，针对每个计划时刻随机选择一个启用场景及其一个事件模板，并将场景名、事件名和开场白快照保存到计划记录。
- 这保证“今日随机事件”在待开始时即可显示 `场景－事件－待开始`，且当日配置后来被编辑也不影响已生成计划。
- 到达计划时间或运营者点击“立即触发”时，均以计划的快照发起报名。
- “立即触发”只作用于待开始项，并复用现有“单群同时只能有一场活跃事件”的约束；发生冲突时返回可读错误，计划保持待开始。
- “调整时间”仍仅作用于待开始项，并继续校验北京时间窗口与最小间隔。

## 运行时详情

- 事件记录保存冻结的事件名称和开场白。
- 事件处于进行中时，仅已加入且未退出的玩家的非指令消息会追加到详情列表。
- 每条详情包括：事件 ID、参与者 ID、真实昵称、消息原文、北京时间、顺序号。
- 机器人消息、未加入者消息、指令消息及玩家退出后的消息不写入详情。
- 详情不会发送到群内；事件结束后仍保留。

## 管理端今日列表

- 每条显示为 `场景－事件－状态` 和计划时间。
- 待开始：显示“立即触发”“调整时间”。
- 进行中、已结束：显示“查看详情”。
- “查看详情”以只读弹窗按顺序展示 `真实昵称：内容` 与北京时间；空详情显示明确空状态。

## API 与测试

- 场景创建/编辑 API 接收和返回事件模板列表，拒绝空名称、空开场白与未知角色变量。
- 今日计划 API 返回场景名、事件名与状态；详情 API 返回当前或历史事件的详情列表。
- 新增立即触发 API，复用后台管理鉴权与写操作版本校验。
- 覆盖：旧数据迁移、计划预选事件、满员后变量渲染、详情记录筛选及顺序、立即触发约束、列表与弹窗数据展示。
