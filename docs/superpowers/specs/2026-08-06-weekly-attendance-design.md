# 连续打卡与周全勤奖设计

**日期：** 2026-08-06  
**状态：** 已确认，待实施

## 目标

增加连续打卡天数与每周全勤奖。员工在上一北京时间自然周（周一至周日）每天均成功打卡后，于下一周周一 00:00 自动获得全勤奖。`/我` 仅展示连续打卡天数。

## 规则

- 每日打卡与周结算均使用北京时间。
- 自然周为周一 00:00 至周日 23:59:59。
- 每周一 00:00 后的每日任务结算上一自然周；只要该周七个日期均存在成功打卡记录，即为全勤。
- 默认全勤奖为 5 摸鱼币；运营者可在既有经济设置中调整，范围与其他奖励一致。
- 全勤奖自动入账，不提供手动领取指令。
- 重复执行任务、服务重启或补跑不得重复发放同一用户同一自然周的奖励。

## 数据与账本

- 新增周全勤结算记录：员工、周起始日期、结算时间、奖励金额；员工与周起始日期唯一。
- 发奖使用现有余额交易账本，来源标记为 `weekly_attendance`，因此自动计入当天正向收益和定时收益榜。
- 结算记录与余额变更在同一数据库事务中写入。

## 连续打卡显示

- 连续天数从当前北京时间日期向前连续统计已有打卡记录；若今天尚未打卡，则从昨天开始统计。
- `/我` 默认回复新增 `连续打卡：{连续打卡天数} 天。`。
- `/我` 的模板变量列表新增 `{连续打卡天数}`，管理员可自行调整回复话术。
- 不显示本周打卡进度、全勤资格进度或领奖提示。

## 管理端与 API

- 经济设置读写 API 返回并接受 `weekly_attendance_reward`。
- 管理端经济设置弹窗增加“每周全勤奖”数字输入，并在设置概览中显示该数值。
- 既有管理员版本控制、幂等键、按钮忙碌状态与成功后刷新继续生效。

## 测试

- 覆盖周一结算、完整七天、缺任一天、不重复结算、跨周及北京时区边界。
- 覆盖连续打卡在当天已打卡与未打卡时的统计规则。
- 覆盖 `/我` 变量渲染、全勤奖账本来源、配置 API 与管理端脚本字段。
