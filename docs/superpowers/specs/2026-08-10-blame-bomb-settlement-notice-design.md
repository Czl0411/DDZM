# 甩锅游戏完整结算通知设计

## 目标

甩锅游戏进入有胜负的终态时，群内只发送一条完整结算通知。通知同时说明结束原因、失败者及其净扣款、获胜者名单、每名获胜者的净奖励和货币名称，避免现有自动路径只显示“谁背锅”而无法确认经济结果。

## 适用路径

以下路径必须使用相同的结算数据：

- 全局倒计时结束并爆炸；
- 当前持锅者操作超时；
- 进行中的玩家发送 `/退出甩锅` 主动退出；
- 玩家指令到达时发现对局已经超时，并由该指令同步完成结算。

报名超时、参与者 `/结束游戏` 和管理员强制结束仍属于无胜负取消，不使用本设计的胜负结算通知。

## 通知格式

自动爆炸：

```text
【甩锅游戏】锅爆炸了，{失败者} 背锅，扣除 {扣除金额} {货币}；{获胜者} 获胜，每人获得 {奖励} {货币}。
```

操作超时：

```text
【甩锅游戏】操作超时，{失败者} 背锅，扣除 {扣除金额} {货币}；{获胜者} 获胜，每人获得 {奖励} {货币}。
```

主动退出：

```text
【甩锅游戏】{失败者} 主动退出并背锅，扣除 {扣除金额} {货币}；{获胜者} 获胜，每人获得 {奖励} {货币}。
```

其中一局有 `N` 名参与者时，`{扣除金额}=N-1`，`{奖励}=1`，`{获胜者}` 按固定玩家编号顺序使用“、”连接。消息展示净经济结果，不展示保证金暂扣和返还的内部流水。

## 实现边界

仓储结算结果已经包含玩家人数、失败者、获胜者和结束原因。自动任务和指令处理器均从该结果构造同一组模板变量，不重新计算或改变余额。根据 `settlement_reason` 选择爆炸、操作超时或主动退出模板，确保同一终态无论由定时任务还是玩家指令触发，通知内容一致。

回复模板继续允许管理员编辑。数据库迁移只把仍等于旧内置默认值的模板升级为完整默认文案；已经被管理员修改的模板原样保留。模板渲染失败时仍回退到新的完整内置默认值。

## 验证

- 仓储测试覆盖自动爆炸和操作超时的出站消息，断言包含失败者、扣款、获胜者、奖励和货币。
- 群指令测试覆盖主动退出以及指令到达时同步处理超时，断言使用对应结束原因且经济内容完整。
- 迁移测试验证旧默认模板会升级、自定义模板不会被覆盖。
- 现有 2–10 人经济守恒和幂等结算测试继续通过。
