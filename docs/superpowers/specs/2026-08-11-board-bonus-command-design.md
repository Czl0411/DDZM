# 核心董事会发奖金指令设计

## 目标

新增核心董事会专用群指令 `/发奖金`，支持向单个员工或全体已入职员工发放系统承担的摸鱼币，并保留逐人余额流水和整次操作审计记录。

## 权限

- 只有当前职位记录中 `is_board=true` 的核心董事会成员可以执行。
- `has_group_management=true` 但不是核心董事会的职位无权执行。
- 发送者未入职或不是核心董事会时，不改变任何余额并返回无权限提示。
- 不设置每日次数、单日金额或累计金额限制。

## 指令格式

- 单人：`/发奖金 员工名 金额`
- 全员：`/发奖金 全部 金额`
- 金额必须是 `1–99999` 的十进制整数，不接受零、负数、小数、符号或额外参数。
- 员工名允许包含空格；解析时首段是 `/发奖金`，末段是金额，中间完整文本是员工名。
- `全部` 是保留目标。目标严格等于 `全部` 时直接进入全员路径，不查询员工姓名，因此不会触发同名拒绝。

## 单人匹配

- 只按去除首尾空白后的完整员工显示名精确匹配。
- 没有匹配时返回员工不存在，不改变余额。
- 匹配多名同名员工时返回名称不唯一，不改变任何余额。
- 唯一匹配时给该员工增加指定金额。

## 全员发放

- 收款范围是执行时数据库中的全部已入职员工。
- 包含发放者本人、其他核心董事会成员和所有普通员工。
- 每位员工获得相同金额。
- 使用一个数据库事务并锁定目标员工；任一写入失败时整次发放回滚，不允许部分成功。

## 资金、流水与审计

- 奖金由系统承担，不从发放者或其他账户扣除。
- 每位收款员工生成一条 `balance_transactions` 流水，`source` 固定为 `board_bonus`。
- 每次成功命令生成一条 `audit_events` 记录，`event_type` 固定为 `board_bonus`。
- 审计记录的 `actor` 保存发放者平台 ID；`payload` 保存发放者显示名、范围 `single/all`、金额、收款人数和总金额。单人发放额外保存收款人平台 ID 与显示名。
- 格式错误、无权限、目标不存在、同名和金额越界均不生成流水或审计记录。
- 入站消息现有幂等机制继续保证同一平台消息 ID 不会重复发放。

## 回复与管理

- 单人成功：`【奖金】{发放者}向{收款人}发放 {金额} {货币}。`
- 全员成功：`【奖金】{发放者}向全体 {人数} 名员工每人发放 {金额} {货币}。`
- 错误场景包括：使用格式、未入职、无权限、员工不存在、名称不唯一、金额无效。
- `/发奖金` 加入指令库、帮助说明和可编辑回复模板；管理员可以停用该指令或修改文案，但不能通过模板改变权限与金额规则。

## 验证

- 核心董事会可向唯一姓名员工发放，余额、流水、审计和群通知一致。
- 核心董事会可向全员发放，包含本人和其他董事会，逐人金额一致且只生成一条操作审计。
- 目标为 `全部` 时不执行姓名匹配，不受同名员工影响。
- 非董事会群管理职位、普通员工和未入职发送者都不能发放。
- 单人同名、不存在和所有非法金额都保持数据库不变。
- 同一平台消息重复投递只发放一次。
- 指令库、帮助和模板管理能读取 `/发奖金`。
