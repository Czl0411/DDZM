# 董事会与后台强制结束游戏设计

## 目标

修复单人记忆考核占用后无法由管理人员释放的问题，并统一群内董事会与管理后台的强制结束能力。

## 权限与指令

- 只有职位记录中 `is_board=true` 的董事会成员可在群内使用 `/结束游戏` 强制结束当前游戏。
- `has_group_management=true` 但不是董事会的职位不获得该能力。
- 普通玩家保持现有规则：只能按各玩法规则结束自己参与的游戏。
- 董事会成员无论是否参与当前游戏，发送 `/结束游戏` 都使用管理员强制结束语义。
- 管理后台登录账号继续通过当前游戏的精确类型和对局 ID 强制结束。

## 核心行为

- 核心强制结束入口补充 `memory_single` 类型，与管理端已经展示的类型保持一致。
- 单人记忆考核被强制结束时，将游戏标记为取消，清除全局占用、答案与报名时限，记录结束时间，并将参与者标记为取消。
- 强制结束不结算胜负，不发放奖励或执行处罚，也不新增玩家稳定记忆事实。
- 结束后只向群内发送一次现有的“管理员已强制结束当前游戏”通知。
- 精确类型和对局 ID 不匹配、对局已经结束或当前存在冲突状态时，不执行结束操作。

## 数据流

1. 群内收到 `/结束游戏` 后读取发送者职位。
2. 如果发送者是董事会成员，读取唯一当前游戏的类型与 ID，并调用现有核心强制结束逻辑。
3. 如果不是董事会成员，继续执行现有参与者结束、退出或投降规则。
4. 管理后台仍通过现有强制结束 API 调用相同核心逻辑。

## 验证

- 董事会未参与单人记忆考核时可用 `/结束游戏` 释放占用。
- 非董事会未参与者仍收到无法结束提示。
- 管理后台可按精确 ID 强制结束单人记忆考核。
- 错误类型、过期 ID 和重复请求继续被拒绝。
- 强制结束只产生一条通知，不产生奖励、处罚或玩家活动记忆。
- 完整自动化测试通过后再部署，并用新入口释放当前卡住的对局。
