# 通用游戏路由、报名超时与蹦蹦数字炸弹改版设计

## 目标

本次改动解决三个直接相关的问题：

1. `/加入`、`/退出`、`/继续`、`/结束游戏` 目前依靠固定游戏顺序逐个试探，可能把实际正在参与的游戏错误路由成谁是卧底等其他玩法。
2. 记忆考核对战等报名状态缺少统一的等待截止时间和释放机制，可能永久占用多人游戏状态。
3. 蹦蹦数字炸弹需要改为不限人数的手动开局，并通过主动私聊提示、周期提醒和参与者跳过机制处理未报数玩家。

同时优化 Browser Worker 的出站发送循环，避免多人私聊提示因每秒只发送一条且重复加入房间而线性变慢。

本设计增量取代 `2026-08-10-bengbeng-number-bomb-game-design.md` 中与创建人数、满员开局、人数上限、超时和报数催促相冲突的部分。旧版精确计算、偏离档位、轮次类型、私聊报数保密、事实记忆边界和结果格式继续有效。

## 不在范围内

- 不改变各游戏已经确认的金币、胜负和处罚规则。
- 不允许管理员在指令库中任意创建新的命令名称。
- 不把 `/结束游戏` 变成绕过各游戏退出代价或权限的免费终止手段。
- 不部署正式环境；实现和验证完成后另行等待部署确认。

## 单一当前游戏视图

核心服务提供一个权威的当前游戏查询器。查询器一次读取发送者身份、发送者正在参与或候选加入的玩法，以及群内唯一的多人报名或活动游戏，返回统一的 `ActiveGameplaySummary`。命令路由和管理端状态都使用该结果，不再分别维护游戏优先级列表。

摘要至少包含：

- 游戏类型和游戏 ID；
- 群 ID、状态、创建时间和当前轮次；
- 发送者身份：发起人、当前参与者、下一轮候选或非参与者；
- 当前状态允许发送者执行的主指令；
- 报名截止时间、下一次提醒时间等当前游戏具备的时限字段。

现有互斥锁继续保证同一群只有一个互斥多人游戏处于报名或活动状态。查询器如果发现历史脏数据导致多个候选，不静默选择某个游戏，而是记录错误并回复“检测到多个活动游戏，请联系管理员处理”，避免再次误命中。

## 通用指令

### `/当前游戏`

向玩家展示：

- 自己当前参与、待加入或待退出的游戏及身份；
- 群内正在报名或进行的多人游戏；
- 当前状态下该玩家可执行的下一步准确指令。

玩家没有参与游戏但群内存在可报名游戏时，也展示该游戏和 `/加入`。完全没有游戏时明确回复当前没有进行中的游戏。

### `/加入`

根据权威摘要加入群内当前可报名游戏；游戏已经开始且支持下一轮候选时，加入下一轮候选。没有可加入游戏时回复实际状态，不继续试探其他玩法。

### `/退出`

命中发送者当前参与或候选加入的真实游戏，并立即提交该游戏定义的退出操作，不增加二次确认：

- 报名阶段立即取消报名；发起人退出后按该玩法规则取消报名或转移发起权。
- 记忆考核对战等待对手时，发起人退出会取消对战且不产生金币和记忆事实。
- 记忆考核对战开始后，退出执行现有投降规则和相应结算。
- 蹦蹦数字炸弹进行中，当前参与者的退出请求立即登记，本轮仍保留并在下一轮开始前移除；下一轮候选退出则立即取消候选资格。
- 其他玩法继续执行各自已经存在的退出后果。

“立即”表示命令无需确认且本次调用马上成功或失败；不改变蹦蹦数字炸弹已经确定的“当前参与者下一轮退出”规则。

### `/继续`

只命中发送者当前参与且正处于等待继续状态的游戏。蹦蹦数字炸弹在有效轮结算后由任一当前参与者继续；单人记忆考核和谁是卧底继续沿用各自规则。没有可继续状态时回复当前游戏和正确下一步。

### `/结束游戏`

先命中发送者实际参与的游戏，再调用该游戏自己的结束规则：

- 蹦蹦数字炸弹、甩锅和谁是卧底继续使用已定义的参与者结束权限。
- 记忆考核对战等待对手时，发起人可取消。
- 记忆考核对战已经开始时，不允许通过 `/结束游戏` 绕过投降结算；命中记忆对战后明确引导发送 `/退出`，不得落到其他游戏的“没有对局”回复。
- 非参与者收到实际游戏名称和权限原因。

管理员后台强制结束使用指定游戏 ID，不受玩家指令权限限制。

### 兼容命令与帮助

保留 `/退出谁是卧底`、`/退出甩锅`、`/投降`、`/摸鱼躲猫猫`、`/me` 等旧命令作为兼容别名。主帮助和 AI 玩法引导只展示新的主指令；深层玩法动作如 `/报数`、`/跳过`、`/答案`、`/躲` 仍按对应状态展示。

## 报名等待超时

所有需要玩家报名或等待对手的玩法都持久化独立的 `signup_deadline`。后台任务按时间顺序领取已到期记录，在事务内确认状态仍是报名中，然后释放占用并向群内发送一次取消通知。

默认值如下：

| 玩法 | 默认报名超时 |
| --- | --- |
| 随机事件 | 15 分钟 |
| 记忆考核对战 | 2 分钟 |
| 谁是卧底 | 2 分钟 |
| 甩锅游戏 | 2 分钟 |
| 蹦蹦数字炸弹 | 2 分钟 |

各值在对应玩法配置中独立保存。已有随机事件、谁是卧底和甩锅设置沿用当前字段；记忆考核对战和蹦蹦数字炸弹新增独立字段。

超时任务只处理报名或等待加入状态。游戏已经开局、已取消、已结束或版本已变化时不再发送通知。核心服务重启后继续使用数据库截止时间处理，不从重启时刻重新计时。

记忆考核对战创建 `waiting_opponent` 状态时必须同时写入截止时间。超时或发起人主动取消均释放多人游戏占用，不扣钱、不生成胜负、不写玩家记忆。

## 蹦蹦数字炸弹生命周期

### 报名 `signup`

- 创建命令改为无人数参数的 `/蹦蹦数字炸弹`，发起人自动成为第一个参与者。
- 旧格式 `/蹦蹦数字炸弹 6` 不再把 `6` 当作目标人数；回复新的准确格式，避免玩家误以为仍会满员自动开局。
- 游戏不设置最大报名人数。
- 玩家发送 `/加入` 报名。
- 创建者和每位加入者都必须已经建立机器人一对一私聊映射；没有映射时，提示“请先私聊机器人发送任意消息，再回群发送对应指令”。
- 任意已报名参与者可发送 `/开始`。少于 3 人时拒绝开始。
- `/开始` 再次校验全部报名者的私聊映射；若有缺失，列出固定编号和名称，保持报名状态且不发送部分私聊提示。
- 报名超过独立配置时间仍未开始时，自动取消并发送群通知。

### 报数 `collecting`

成功开始后锁定本轮参与名单并执行以下动作：

1. 轮次加一或初始化为第 1 轮。
2. 清空本轮提交和跳过开放标志。
3. 为每位参与者排队一条一对一消息：`请按这个格式报数给我 /报数 数字`。
4. 持久化下一次群提醒时间，默认是开轮后 15 秒。

参与编号在整场游戏中保持稳定，按首次成为当前参与者的顺序递增；被移除的编号不复用。每轮群提示按编号和当前显示名列出未报数玩家。

报数仍只能在私聊中使用 `/报数 1-100`。第一份合法提交锁定且不能修改；群内报数、格式错误、越界、重复报数或非参与者报数只返回对应错误，不改变提醒时间。

### 未报数提醒与 `/跳过`

- 到达提醒时间后，后台任务在群内发送尚未报数的编号和名称。
- 第一次成功生成提醒后将本轮 `skip_enabled` 设为真，并将下一提醒时间推进一个配置间隔。
- 只要仍有未报数玩家，后续按间隔继续提醒；没有未报数玩家或状态变化后停止。
- 第一次提醒前发送 `/跳过` 会提示尚未开放。
- 任意当前参与者可使用 `/跳过 2 4` 一次排除多个仍未报数玩家。
- `/跳过 唯一名称` 作为兼容写法；重名、未知编号、已经报数、已经移除或重复目标均给出明确反馈。
- 有效跳过目标从整场游戏中移除，不进入后续轮次，也不产生本轮胜负或记忆事实。
- 跳过后当前参与者少于 3 人，立即结束整场并通知人数不足。
- 跳过后其余当前参与者都已报数且人数不少于 3 人，立即进入本轮结算。

报数阶段不设置无操作自动解散。处理卡局只使用周期提醒、`/跳过`、参与者 `/结束游戏` 或管理员强制结束。

### 结算与等待继续 `waiting_continue`

结算继续使用原设计的精确公式、不同偏离档位、并列胜出/受罚、真心话/大冒险周期和三段式群消息。有效轮进入 `waiting_continue`；无效轮清空提交并重新开始同一轮报数，同时重新私聊提醒当前参与者。

游戏进行中：

- 非参与者发送 `/加入`，在私聊映射校验通过后进入下一轮候选，并分配不会复用的稳定编号。
- 当前参与者发送 `/退出`，立即登记为下一轮退出，本轮仍参与结算。
- 候选者发送 `/退出`，立即取消下一轮加入。
- 任一当前参与者在 `waiting_continue` 发送 `/继续`，系统先应用待退出和待加入，再开始下一轮。
- 应用人员变更后少于 3 人，结束整场。

开局后的 `collecting` 和 `waiting_continue` 都不使用无操作自动解散。整场只能由参与者 `/结束游戏`、管理员强制结束、跳过后人数不足或继续时人数不足而结束。

## 消息发送性能

现有 Browser Worker 每次循环最多领取一条出站消息，并在每条 Socket 消息发送前重复执行 `message:join-room`。多人开轮时，私聊提示会以约每条 1–2 秒的速度串行积压。

改动保持现有出站队列和逐条 Socket ack 语义，只做两个局部优化：

1. `AikdaSocketGateway` 复用已经成功加入的一对一房间；只有连接重建、缓存失效或目标房间尚未加入时才调用 `message:join-room`。
2. Browser Worker 每个循环连续领取并发送一个有上限的小批次，直到队列为空、达到批次数量或达到本轮时间预算。每条消息仍按队列顺序发送并独立确认，不并行洪泛。

处理完批次后继续执行入站读取、心跳和其他既有任务，避免大量私聊提示饿死群消息接收。发送失败仍沿用现有重试和幂等机制；失败消息不能阻止后续循环恢复。

## 管理端

### 统一当前游戏面板

管理端读取与玩家 `/当前游戏` 相同的权威摘要，展示：

- 游戏名称、状态、游戏 ID、开始或报名持续时间；
- 发起人、当前参与者、下一轮候选和待退出者；
- 报名截止时间、下一提醒时间和当前轮次；
- 对应游戏允许展示的进度信息。

管理员可选择明确的游戏 ID 强制结束。强制结束向群内发送管理员终止通知，释放游戏占用，不补做胜负、金币、处罚或玩家记忆。

### 蹦蹦数字炸弹配置

增加独立管理区块：

- 启用或停用创建新游戏；
- 报名超时，默认 2 分钟；
- 未报数群提醒间隔，默认 15 秒；
- 当前轮次、参与者、已报数和未报数名单；
- 下一次提醒时间；
- 强制结束按钮。

停用只阻止创建新游戏，不直接杀死已经存在的游戏。配置保存后，新报名使用新的报名超时；活动报数轮从下一次提醒推进时使用最新提醒间隔。

## 持久化、并发与幂等

- 当前游戏摘要只读持久化状态，不额外创建第二套活动状态。
- 报名截止、提醒截止、`skip_enabled`、稳定编号、下一轮加入/退出和私聊映射校验结果所需标识均持久化。
- 创建、加入、退出、开始、报数、跳过、继续、结束和到期任务都使用现有玩法顺序锁，并在事务中锁定活动游戏。
- 提醒任务以“状态 + 轮次 + 下次提醒时间”作为幂等门槛；重复 Worker 或任务重试最多生成一条同轮同时间窗提醒。
- 最后一份报数、跳过最后一个未报数者和并发结束只能有一个事务进入结算。
- Core 和 Browser Worker 重启后恢复报名截止、报数状态和下一次提醒；不会重新编号、重复私聊、重复结算或重复群提醒。
- 已部署的 `/记忆考核 对战` `multiplayer_active` 热修必须保留并纳入回归测试。

## 回复模板、帮助与玩家记忆

新增或调整的固定回复继续接入现有回复模板体系，包括：

- 当前游戏摘要和无游戏状态；
- 通用加入、退出、继续、结束的状态或权限反馈；
- 各玩法报名超时通知；
- 数字炸弹私聊前置提示、开局私聊、未报数提醒、跳过反馈和人数不足结束；
- 管理员强制结束通知。

玩法帮助和 AI 知识只解释规则并引导准确指令，不替玩家执行命令。游戏命令和中间话术不进入稳定玩家印象；只在有效结算时记录参与、胜出、受罚、真心话或大冒险等事实。被跳过、报名超时、主动取消或管理员强制结束不生成胜负事实。

## 错误反馈原则

- 命令首先解释实际命中的游戏，不使用其他玩法的兜底文案。
- 缺少私聊映射时明确给出建立私聊和重新发送命令的步骤。
- `/开始` 人数不足或存在无私聊映射玩家时不产生部分开局副作用。
- `/跳过` 未开放、无权限、目标无效或目标已报数时说明具体原因。
- 玩家同时处于不应并存的多个游戏状态时停止写操作并提示联系管理员，不猜测目标。

## 验证标准

### 通用路由与报名超时

- 为每个游戏状态构造路由测试，证明 `/加入`、`/退出`、`/继续`、`/结束游戏` 命中真实游戏且不会落到谁是卧底等错误回复。
- 验证 `/当前游戏` 的个人状态、全局报名状态和下一步指令。
- 验证旧命令别名仍可用，但主帮助只展示主指令。
- 验证五类报名超时分别使用独立配置、只通知一次、重启后继续且释放全局占用。
- 回归记忆对战等待发起人退出、超时取消、开局投降及 `multiplayer_active` 映射。

### 蹦蹦数字炸弹

- 验证无人数参数创建、发起人自动加入、不限最大人数、至少 3 人和任意参与者开始。
- 验证创建、加入和开始时的私聊映射门禁，以及开始失败不发送部分私聊。
- 验证每位参与者收到一次正确私聊提示，数字仍只在私聊接收和回复。
- 使用可控时钟验证首次 15 秒提醒、跳过开放、重复提醒和状态变化后停止提醒。
- 验证编号固定、批量编号跳过、唯一名称兼容、重名拒绝、已报数不可跳过。
- 验证被跳过者从整场移除、跳过后直接结算、少于 3 人结束和并发幂等。
- 验证游戏中下一轮加入、下一轮退出、继续应用名单和无人数上限。
- 验证开局后不会因无操作自动解散，参与者结束和管理员强制结束都释放占用且不重复结算。
- 回归原有精确计算、并列档位、无效轮重开、轮次周期、结果格式和玩家记忆边界。

### 消息性能与管理端

- 验证已加入房间不重复调用 `join-room`，连接重建后会重新加入。
- 验证 Worker 单循环发送有界批次、保持顺序、逐条确认，并在批次后继续处理入站和心跳。
- 管理端测试覆盖统一状态、独立配置、启停和按游戏 ID 强制结束。
- 运行完整测试套件，确保现有游戏、随机事件、AI、记忆、管理端和 Socket 消息不回归。
