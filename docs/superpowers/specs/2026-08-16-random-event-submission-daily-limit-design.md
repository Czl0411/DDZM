# 随机事件投稿每日一次限制设计

## 目标

每名已入职员工每天最多将一份随机事件投稿正式提交审核。限制用于控制正式投稿数量，不妨碍玩家在私聊中创建和编辑草稿。

## 计次规则

- 以北京时间自然日为边界，每日上限固定为 `1`，暂不增加管理端配置。
- 仅当玩家发送 `/确认投稿`，且投稿成功从草稿变为待审核时计次。
- 创建、继续编辑、取消或超时的草稿不计次。
- 已正式提交的投稿即使随后撤回、审核通过或审核未通过，仍占用提交当天的次数。
- 北京时间次日 `00:00` 后自然恢复，无需定时清零任务。

## 实现方式

复用 `random_event_submissions.submitted_at`，不新增计数表或数据库字段。

`confirm_random_event_submission()` 已在同一事务内以 `FOR UPDATE` 锁定当前用户。完成现有投稿状态检查后、将草稿改为待审核前，查询该用户是否存在 `submitted_at` 落在北京时间当天半开区间 `[当天 00:00, 次日 00:00)` 的投稿记录。

若存在，拒绝本次确认并保留当前草稿，返回：

`你今天已经投稿过一次，请明天再来。`

用户行锁将同一玩家的并发确认串行化，确保两个同时到达的 `/确认投稿` 最多只有一个成功。不同玩家之间互不阻塞。

## 流程与兼容性

1. 群内或私聊启动投稿仍沿用现有入职与私聊房间检查。
2. 玩家可正常完成向导并进入预览。
3. `/确认投稿` 先执行现有开放状态、员工、待审核稿和草稿完整性校验，再执行每日次数校验。
4. 命中每日限制时不改变草稿状态、内容或过期时间。草稿继续遵循现有超时规则；若到次日时已经超时，玩家需重新开始投稿。
5. 历史投稿已经具有 `submitted_at`，上线当天会自然参与判断，无需数据迁移。

## 测试与验收

- 当天首次确认投稿成功。
- 同一玩家当天第二次确认被拒绝，且第二份草稿状态、内容和既有过期时间不变。
- 当天已提交的投稿撤回后仍不能再次确认。
- 当天已提交的投稿审核通过或驳回后仍不能再次确认。
- 到北京时间次日后可以再次确认。
- 同一玩家并发确认时最多一份成功。
- 不同玩家可在同一天各自提交一份。
- 现有投稿向导、私聊引导、审核和撤回测试继续通过。

## 非目标

- 不增加每日次数的后台配置。
- 不限制草稿创建或编辑次数。
- 不改变“同一玩家最多一份待审核投稿”的既有规则。
- 不自动删除或取消因每日限制而暂未提交的草稿。
