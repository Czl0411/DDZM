# 黑历史册 · 设计方案（待实施）

> 状态：**已确认设计，待用户复核规格后实施**。
> 目标：让群成员能花少量摸鱼币把一句群聊保存为某人的“黑历史”，之后免费随机翻出；本人只能在私聊中付费删除自己的记录。

## 1. 已确认的玩法

| 操作 | 地点与格式 | 结果 |
| --- | --- | --- |
| 记入 | 在群内**回复一条文字或图片消息**发送 `/q` | 执行者支付 **1 摸鱼币**；记录归被回复消息的作者 |
| 翻出 | 在群内**回复目标玩家任意一条消息**发送 `/黑历史` | 免费；从目标玩家尚未删除的记录中等概率抽取一条，并发送到当前群 |
| 删除 | 私聊总监事发送 `/删除黑历史` | 只列出自己的记录；再用 `/删除黑历史 编号` 删除一条，收费 **5 摸鱼币** |

`/q` 和 `/黑历史` 都允许对自己使用。任何员工都可以对他人的公开群聊发言使用这两个命令；删除权限仅属于记录的归属者。

## 2. 群内交互

### 2.1 `/q`

1. 必须来自已启用监听的群，并且消息必须带有效回复引用。
2. 被引用消息仅接受 `text` 或 `image`；Bot、系统通告、空文字和无图址图片拒绝记录。
3. 执行者余额不足时拒绝，不创建记录。
4. 相同群聊中的同一条平台消息只保存一次：首次成功者扣币；以后再 `/q` 回复该消息只提示“这条已经在册”，不重复扣币、不制造抽取权重。
5. 成功后群内只回复一条简短的“已记入 X 的黑历史册”，不公开原文，避免记录动作本身造成刷屏。

记录要冻结当时的文字或图片 URL、原消息平台 ID、群聊、消息作者和记录时间；原消息日后被撤回或编辑，不修改已存记录。

### 2.2 `/黑历史`

1. 必须回复目标员工的一条群消息，用回复作者准确定位，避免昵称歧义。
2. 从该员工未删除的全部记录等概率随机抽取一条；无记录时给出明确提示。
3. 文字记录：Bot 生成一张统一的黑历史卡片图片，包含“@员工名称 · 职位”、原文和“黑历史册”标识；不显示记录者是谁。
4. 图片记录：Bot 先发一条简短的“翻出了 X 的一条黑历史”，随后原样转发当时保存的图片 URL；不压缩、不嵌入截图卡。
5. 若平台图片 URL 已失效，Bot 明确提示该图片已失效，不扣费，也不自动删除该记录。

抽取不支持按关键词、编号或时间指定内容，保持“随机抽卡”的玩法感。

## 3. 私聊删除

`/删除黑历史` 在总监事私聊中展示仅属于发令者的记录，按 5 条分页，附序号、文字前 30 字或“[图片]”、记录日期，并提供 `/下一页`。

`/删除黑历史 编号`：

- 只能删除列表中属于自己的条目；
- 确认余额至少为 5 后扣款并删除；
- 删除成功后返回剩余条数；
- 编号不存在、已删除或余额不足均不扣款。

群内发送删除指令只提示“请私聊总监事管理自己的黑历史”，不会泄露编号或内容。

## 4. 数据与边界

新增 `black_history_entries`：

| 字段 | 用途 |
| --- | --- |
| `id` | 对玩家展示的稳定编号 |
| `subject_user_id` | 黑历史归属者（被引用消息作者） |
| `recorder_user_id` | 记入者，仅用于审计，不在群内展示 |
| `group_chat_id`、`source_platform_message_id` | 来源及全局去重键 |
| `content_type`、`text_content`、`image_url`、`image_alt` | 冻结的文字或图片引用 |
| `created_at` | 记入时间 |

唯一约束为 `(group_chat_id, source_platform_message_id)`。删除使用物理删除；摸鱼币扣款仍保留在既有余额流水里。

本期不增加后台管理页、搜索、申诉、批量删除、记录上限或自动过期，也不保存私聊内容。

## 5. 实现边界与验证

- Socket 入站的回复引用已经携带文字、图片 URL、作者平台 ID 和消息 ID；不需要改消息协议。
- 文字卡片由现有浏览器运行时渲染为图片后，通过既有图片出站通道发送；图片记录复用既有图片出站通道。
- 所有扣币通过现有账户余额流水完成，不能在扣币失败后留下记录。
- 需要覆盖：自己/他人记入、文字/图片、重复引用、余额不足、无回复、无记录、随机抽取、私聊分页删除、越权删除、图片失效和出站内容。

## 6. 明确不做的事

- 不允许用 `/黑历史 名称` 按昵称定位；必须回复消息。
- 不公开记录者身份。
- 不让他人删除、编辑或指定抽取某人的记录。
- 不把图片二次裁剪、合成或降低清晰度。
