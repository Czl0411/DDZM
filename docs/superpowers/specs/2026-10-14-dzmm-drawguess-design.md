# 群聊你画我猜设计

日期：2026-10-14。状态：聊天方案已确认；本文待用户审阅，尚未实施。

## 目标与范围

为现有 DZMM 群友提供独立 Gamefy 游戏：3～8 人轮流作画、实时猜词、累计积分排名。界面与交互参考中国成熟移动休闲游戏的通用习惯，采用原创视觉，不复制其他产品素材。与象棋、斗地主并行，不修改它们的规则，不接摸鱼币、津贴、下注或付费 AI。

已确认：三选一词语、15 秒选词、90 秒作画，每人画两次；猜中后不公开答案；全部猜中或时间到揭晓；猜手基础 50 分及最高 50 分时间奖励，画手每有一人猜中获 20 分；同分并列。群指令配独立分享卡及入座码文本，已入职成员参加，至少三人且全员准备后由房主开始，中途加入者仅观战。画手、已猜中者在本题结束前禁自由文字，观众不能猜词或聊天。

以下边界细节是本稿建议，随本文一并审阅：继续使用已有 UID 信任模式、断线不暂停计时、5 秒揭晓、固定参赛名单、超时自动选词、首版内置词库。它们不是已上线能力。

## 技术路径比较

1. **推荐：沿用现有后端与员工数据库，新建独立游戏模块。** 服务端负责房间、题目、画布事件、积分；H5 负责显示及操作，HTTP 提交、SSE 接收。无需新增运行服务，能复用现有部署和员工查询，但必须控制绘画事件频率及数据库写入量。
2. 全部使用 Gamefy 服务端函数及平台存储：需要重新接入员工身份和实时房间同步，首版集成成本更高。
3. 新建专用 WebSocket 服务：适合更大规模实时绘画，但增加部署、连接管理和维护成本，首版不采用。

新代码位于独立 `drawguess_*` 后端模块及 `gamefy/drawguess/`。仅在既有指令路由、配置、定时推进入口增加必要接入，不抽象或重构象棋、斗地主。

## 入场与房间

- 在配置开放且已监听的群中发送 `/你画我猜`，创建房间。Bot 分开发送 character 游戏分享卡和文本：四位入座码、10 分钟入座有效期、加入/观战说明。不把长链接拼进卡片内容。
- 创建者占第一席并为房主，其他已入职成员输入码抢剩余席位，最多八人。服务端原子检查席位，重复提交不会重复占位；本人再次进入恢复原席。
- 码在有效候场房间范围内唯一，不作为身份证明。过期未开始房间关闭；开始后码失效，不允许补入正在进行的一局。
- 候场显示八个头像席位、姓名、房主、准备状态及当前人数。所有在席者（包括房主）准备后，房主才可开始；人数不足或未全准备时明确显示原因。
- 候场主动退出释放席位；房主退出由最早入座的剩余成员接任。断线不等于退出，不立即清除准备或席位；候场到期统一关闭。
- 开局冻结名单及入座顺序，两轮依次轮流作画，共 `人数 × 2` 题。进行中退出仍保留参赛席位、已获积分与轮次，允许重连，不允许替换玩家。
- 中途新访客仅观战。结束页显示排名和“再来一局”；由房主确认后回到同房间候场，积分清零、全员取消准备、刷新入座码及有效期，观众可以抢空席。开始新局前必须再次全员准备。

## 单题流程与计分

状态：候场 → 选词 → 作画猜词 → 揭晓 → 下一题选词 → 最终排名。

- 服务端抽取三个未在本局使用过的候选词，仅发给当前画手。15 秒内选择一个；超时从三者随机选一个，立即进入 90 秒作画。
- 其他玩家及观众只显示词语字数，不显示分类、首字、候选词或答案。首版使用内置、人工检查的常用中文词库，不调用生成式 AI。
- 猜词以服务端收到时间判定。先推进已到期状态，再处理请求，截止后不计分。
- 匹配规则为 Unicode NFKC 规范化、去首尾空白及大小写折叠后的完整匹配；同义词仅限词库显式别名。不做模糊匹配，不把错别字或包含答案的长句判为正确。
- 答对得 `50 + floor(50 × 剩余毫秒 / 90000)` 分，奖励范围 50～100。每人每题只结算一次；画手同时增加 20 分；答错不扣分。
- 错误猜测显示在本题消息区；正确猜测内容不广播，替换为“姓名已猜中 +分数”。本人显示答对反馈，随后锁定本题输入。服务端同样拒绝绕过 UI 的聊天或猜词。
- 所有参赛者中除画手外均猜中，或 90 秒到期，进入 5 秒揭晓，公布答案、本题得分及累计分，然后自动下一题。断线者仍在猜手名单内，可能使该题等到截止，不另写在线判断规则。
- 断线画手仍按正常超时流程推进，该题计入其两次作画机会，不暂停或补时；重连到截止前可以继续画。
- 完成全部题目后按总分降序排名，同分并列，采用 1、1、3 的名次显示。结算和重复定时触发幂等，不重复发分。

## 聊天与画布

- 候场、揭晓及最终排名时，在席玩家可聊天；作画阶段仅未答对的猜手可发送文字，统一作为猜词处理。选词阶段允许非画手的在席玩家聊天。观众全程只读。
- 画手工具：画笔、预设颜色、三档粗细、橡皮、撤销最后一笔、清空。清空二次确认；撤销、清空只作用于当前题。
- 统一 4:3 逻辑画布；各端等比显示，以归一化坐标、归一化笔宽传输，避免不同设备画错位置。高分屏正确缩放，不拉伸画面。
- Pointer Events 支持触屏和鼠标；只在画布绘制区域阻止页面滚动，处理取消触摸，避免离开画布后误连线。默认不提供图片上传、文字工具或导出。
- 本地即时绘制，约每 100 毫秒批量提交采样点；服务端每房间分配单调事件序号，客户端按序应用与去重。失败批次保留操作 ID，可安全重试；不得无界重试或重复画线。
- 每批最多 256 点、16 KiB；当前题最多 30,000 点；超过时保留已有内容并提示“本题画布已达上限”，仍可撤销或清空。新笔触与接收端都验证坐标、颜色及笔宽，不允许任意绘制脚本。
- 一题结束清理活动画布事件；重连只重放当前题有限事件及当前状态，不返回整局绘画历史。不提供回放库或永久画作保存。
- 文字最多 100 字，每人每秒一次，展示为纯文本。正常聊天防刷不能阻塞房间状态和绘画同步。

## 身份、同步与隔离

- 默认继承既有 UID 信任模式：SDK 取得玩家 UID，后端查员工登记并判断房间身份。不要求平台登录 token，不使用开发者密钥作为玩家凭证。
- **风险明确：客户端 UID 可以被伪造，查员工表不等于证明操作者身份。** 此方案只适用于用户已接受的无资产休闲玩法；不宣称能防冒名，不将它扩展到余额或管理权限。
- 服务端保存权威状态，负责房间锁、截止时间、席位、词语、答案判断与计分。客户端提交选择/笔触/猜词，不提交有效积分或最终胜负。
- 对每个读取和推送请求按身份投影数据：候选词及答案只给当前画手；其他人即使查看网络响应也不应看到答案。揭晓后才向所有人发送答案。日志不记录 UID 明文、答案、聊天原文或开发密钥。
- 新建独立房间、当前题画布事件、文字消息及幂等记录的持久化存储；迁移基于实施时真实迁移头编写。笔触批量追加，不每个点重写整个房间 JSON。SSE 使用游标读取增量，慢客户端限流后重取快照，不能积压无限队列。
- 页面先拉取带事件游标的快照，再订阅游标之后的更新，避免两步之间丢笔触。换房/回大厅会取消旧订阅；异步旧请求不能覆盖新房间。
- Gamefy KV 仅存最后房间定位，不存权威积分或画布；存储异常不能阻止大厅可用。重开优先恢复仍有效的本人房间，返回大厅清除定位。禁止用 URL hash 导航，避免平台重载问题。
- 身份、列表、房间请求设置 8 秒超时，展示可理解的失败信息和重试按钮，不永久遮罩、不密集重试。SDK ready 在可操作界面出现后调用；启动诊断不携带敏感内容。
- 服务重启后从持久状态恢复，按服务端时间推进过期阶段；不重复结算。定时器只作触发，数据库状态及截止时间是最终依据。

## 原创手机优先 UI

参考玩吧、会玩的中文休闲社交产品定位与常见操作习惯，而非逐像素复制具体页面。公开参考：[玩吧](https://apps.apple.com/cn/app/id609377731)、[会玩](https://huiwan.wepie.com/about)。

- 视觉：暖白底、墨色正文、珊瑚橙主操作、蓝色辅助状态；圆角头像和轻量卡片，用画笔/涂鸦元素体现主题，不沿用斗地主绿色牌桌。
- 大厅：名称、简短规则、房间人数及状态、本人房间优先，不以 UUID 作为主标题。空状态告诉用户去开放群发指令。
- 游戏页：顶部轮次/倒计时，紧接横向玩家头像积分条；中央大画布；画手底部工具栏，猜手底部消息区及固定输入框。自己的回合、已猜中、观战身份明确可见。
- 绘画区不被工具浮层遮挡；工具选中状态明显；按钮点击区域至少 44px。中文输入法组合过程中回车不误发送，键盘弹出后输入框仍可见，兼容安全区。
- 选词为三张大词卡加倒计时；揭晓显示答案和本题增分；排名突出前三名但所有成员都有得分，提供再来一局/返回大厅。
- 输入不可用时说明具体原因：“你正在作画”“你已猜中，等待揭晓”“观战中，仅可查看”，不显示无解释的灰按钮。
- 正常加载、空房间、失败、断线重连分别呈现，允许退出，不用无限旋转动画掩盖错误。桌面使用画布与消息侧栏，手机主流程无需横屏。

## 验收与发布边界

1. 规则单测：3/8 人边界、两轮顺序、选词与作画截止、时间奖励上下界、重复猜中、并列排名、断线推进、全员猜中提前结束、重启后幂等。
2. API/并发测试：第八席竞争、准备及开局竞争、过期码、非员工、观众/非画手越权、旧题笔触、重复请求；任意非画手响应均不泄漏候选词及答案。
3. 画布测试：两端笔触一致、批次乱序去重、橡皮撤销清空、断线重放、快照订阅间隙、速率/大小上限。八客户端基准下不得逐点数据库写入或出现无界队列。
4. 浏览器测试：320/390px 手机及桌面布局，中文输入、软键盘、安全区、触屏不误滚动；真机 iPhone Safari、Android 实测，不能把桌面模拟测试描述为真机验证。
5. 人工三人完整走完六题，验证卡片/文本分发、入座、准备、轮换、正确答案隐藏、积分排名、再来一局。模拟掉线、切后台、重复打开和服务重启。
6. 只添加本游戏所需代码及配置；回归象棋、斗地主的开房与分享链路；不捎带提交当前工作区无关修改。
7. 必须使用新的独立 Gamefy 卡。卡 ID 尚未提供，提供或授权创建之前仅完成本地实现与测试，不覆盖象棋 3761638 或斗地主 3763357，不擅自公开上架。
8. 用户审阅本文后再编写实施计划。后续先测试群验收，收到开放指令再切换正式群；部署前备份，记录代码版本、迁移与回滚步骤。
